# 4.4.c tutor notes

Notes for the pre- and post-lecture tutor posts.

## The intuition to hold onto
Carry this question into the lecture: if you found just *one* of these clues on a device, a new admin account, say, would you be confident it was an attack? Almost certainly not; an IT technician doing routine maintenance produces the exact same artifact. That ambiguity is the whole reason this skill exists: an indicator of compromise is evidence, not proof, and the skill being taught is exactly the same one from log analysis one atom ago, refusing to trust a single data point and instead asking what the *combination* of data points implies.

## The big picture
The Meridian scenario ties this entire unit together on purpose: a new unauthorized admin account (a 4.2.d least-privilege violation), a disabled antivirus service (defeating 4.3.b's endpoint protection), and an outbound connection to a known-malicious IP (the exact network-based IOC signature EDR watches for in 4.4.a), three artifacts that are individually explainable but collectively describe one coherent attack story: gain access, disable the tooling that might catch you, establish persistence, phone home. Weighted scoring is worth connecting explicitly back to CVSS from 4.3.c, because it's the same underlying move applied to a different question, instead of "how severe is this vulnerability," it's "how strongly does this specific artifact suggest compromise", and both exist for the identical reason: fuzzy, instinctive risk judgment doesn't scale, but a number compared against a threshold does. Last, keep IOC and IOA cleanly separated, because it's a distinction about *timing*, not severity: an IOC is evidence a step already happened (a file with a `.locked` extension already sitting on disk), while an IOA tries to catch the attacker's technique while it's still unfolding (a process starting to enumerate files by extension, which is exactly what ransomware does in the seconds before encryption begins), and that's a fitting place to end Unit 4, because it's the same idea the whole unit has been building toward: the earlier in the attack chain you can reliably recognize what's happening, the more of the damage in 4.1's malware section never gets the chance to occur at all.
