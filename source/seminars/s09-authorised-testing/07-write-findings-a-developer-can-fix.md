## 7. Write findings a developer can fix

A finding nobody can reproduce doesn't get fixed. For each one: the exact request, what came back, why it works, the fix in code terms, and the retest. Keep the data out: say what you saw, not the customer's address.

```tool report
{"tpl": "findings", "title": "Penetration test findings: NimbuMart, 16 to 20 November 2026", "text": "# Penetration test findings: NimbuMart, 16 to 20 November 2026\n\n## Rules of engagement\n\nAs agreed in the letter of 12 November (see the rules of engagement): nimbu.shop and its /api, 192.0.2.10 and 192.0.2.11. 192.0.2.12 was not touched. Only the demo account was used.\n\n## Executive summary\n\nThree weaknesses let an outsider log in as the shop's administrator, read other customers' orders, and make the staging API believe they are anyone. All three are quick to fix. The first should be fixed before the weekend.\n\n## Findings\n\n**NM-01 Login bypass by SQL injection (critical, CVSS 9.8).** Reproduce: POST /api/login with `{\"email\":\"admin@nimbu.shop'--\",\"password\":\"x\"}`; the response is 200 with role admin. Cause: the email is pasted into the SQL query. Fix: a parameterised query (`WHERE email = ? AND password = ?`). Retest: the same request returns 401.\n\n**NM-02 Any customer can read any order (high in practice, CVSS 6.5).** Reproduce: log in as demo@nimbu.shop; GET /api/orders/2 returns another customer's order, including a delivery address. Cause: the query checks the order ID only. Fix: `WHERE id = ? AND user_id = ?` with the caller's ID from the token; return 404 otherwise. Retest: order 2 returns 404 for the demo account.\n\n**NM-03 Staging tokens can be forged (critical, CVSS 9.1).** Reproduce: take DEMO_TOKEN from http://api-staging.nimbu.shop:8080/static/app.bundle.js; its HS256 secret is a dictionary word (checked offline against a 12-word list). Fix: a 32-byte random secret from the vault, rotated; remove the token from the bundle; put staging behind the VPN and close port 8080 to the internet. Retest: the old token is rejected; the secret isn't in any wordlist.\n\n## What went well\n\nPasswords are hashed; the payment page is separated and run by a provider; error messages on most pages don't show internals.\n\n## Retest\n\nBooked for Wednesday 25 November, same scope, same account.\n", "n": 5, "blank": ["text"]}
```
