Network lab 1: Your first network (Filius)

Beginner · about 30 min

Install Filius, cable four computers to a switch, give them addresses, and prove with ping which ones can talk and why one can't.

WalkthroughPracticeSolo

The files for this seminar are in ~/case (Linux) and case/ (Python): README.txt.

1. Install Filius and meet the two modes

Every network lab in this set happens in a free program on your own computer, and you answer here as you go. Filius is free and open source, made for school network lessons. Download it from https://www.lernsoftware-filius.de (Windows installer, or the .zip that runs anywhere with Java). Start it and pick English.

Filius has two modes. Design mode (the hammer) is where you place devices, cables and settings. Simulation mode (the green play arrow) is where the network runs and you use the computers.

  • ☐ Filius installed and open in English
  • ☐ Find the hammer (design) and the green arrow (simulation)
  • ☐ Find Computer, Switch and Cable in the left-hand bar

Hint: If Filius won't start from the .zip, install Java first, or use the Windows installer.

Question: Which mode do you use to place and cable devices? (one word)

2. Cable four computers to a switch

In design mode, drag one Switch and four Computers onto the canvas. Pick the Cable tool and click a computer, then the switch: Filius picks a free port for you. Cable all four.

Click each computer and type its name, IP address and netmask from the plan in README.txt. Give the fourth one the wrong address on purpose: 192.168.2.14.

  • ☐ Four computers cabled to one switch
  • ☐ Names and addresses typed from the plan
  • ☐ "stray" has 192.168.2.14 (wrong on purpose)

Hint: Tick "Use IP address as name" off, so the names show on the canvas.

Question: What netmask did you give the computers? (dotted)

3. Ping, and explain the one that fails

Press the green arrow. Click till-1, open Software installation, add Command line, and press Apply. Open the command line and type ipconfig, then ping 192.168.1.12 and ping 192.168.1.13. Then ping 192.168.2.14.

The first two answer. The last one doesn't, even though the cable and the switch are fine: 192.168.2.14 is in a different network (192.168.2.0/24), and till-1 has no router to send it to.

  • ☐ ipconfig shows till-1's address and netmask
  • ☐ Pings to till-2 and office get replies
  • ☐ Ping to stray fails: write one line on why

Hint: Same cable, same switch, different network number. Computers only talk directly to addresses inside their own network.

Question: Can till-1 reach stray at 192.168.2.14? (yes or no) Question: Which command shows a computer's own address in Filius? (one word)

4. Fix it and watch the data exchange

Go back to design mode and change stray to 192.168.1.14. Run again and ping it: it answers now.

Right-click till-1 and choose Show data exchange. Ping once more and read the list. Before the first ping you'll see ARP: till-1 shouts "who has 192.168.1.14?" and stray answers with its MAC address. Then come the ICMP echo request and echo reply.

  • ☐ stray moved to 192.168.1.14 and it answers
  • ☐ Data exchange window open
  • ☐ Find the ARP question and answer before the first ICMP packet

Hint: ARP only happens once: the answer is remembered for a while.

Question: Which protocol finds a MAC address before the first ping? (three letters)
