Teacher case: smishing and quishing guide

The QR code parking fine

Beginner · about 20 min

Fake parking fines arrive by text and by QR stickers on parking meters. Compare the fake site with the real one and find where the card details go.

Worked exampleGuidedOn your own

Saturday 7 Nov. The Elmbridge Council helpdesk is getting calls about parking fines. Some people got a text; others scanned a QR code on a parking meter. Some paid, and their cards were then used abroad. You are helping the council's IT team.

The evidence is in ~/case (Linux) and case/ (Python). The network tools (nmap, curl, dig, whois, openssl and more) work on a recorded copy of the case network; nothing leaves your browser.

What you'll learn

  • What smishing (SMS phishing) and quishing (QR phishing) look like
  • Compare a fake domain with the real one using dig, whois and certificates
  • Read a phishing page safely with curl to see where the card details go

How to use this runbook

  • Run a cell with Shift+Enter (or its Run button). Run the cells in order: the first Linux cell copies the evidence into ~/case.
  • Tick each - [ ] box when you have done it.
  • Stuck? Open a Hint under the step.
  • Type your answer into each check box and it tells you if you are right. Answers are short: an address, a name, a number or a time such as 09:05.
  • Write your notes under each step. Download .ipynb keeps your notes and every output.

3. Real or fake?

  • ☐ Where does each domain point, and who owns that address?
  • ☐ When was each domain registered?
  • ☐ Both have a padlock: when were their certificates issued? Does a padlock prove a site is honest?

Hint: whois shows Created:. The first report came on 7 Nov. Question: How many days old was the fake domain on 7 Nov? Question: Which IP address hosts the fake site?

dig +short elmbridge-parkpay.example
dig +short pay.elmbridge-council.test
echo ---
whois elmbridge-parkpay.example
whois elmbridge-council.test
echo ---
openssl s_client -connect elmbridge-parkpay.example:443 | grep -E 'subject=|NotBefore'
openssl s_client -connect pay.elmbridge-council.test:443 | grep -E 'subject=|NotBefore'

4. Read the fake page (safely)

curl downloads the page as text. Nothing on it runs, so this is a safe way to look.

  • ☐ What does the form ask for?
  • ☐ Where does it send the details?
  • ☐ Phishing kits often leave a build comment in the HTML: that is the flag

Hint: The action= of the form is where the data goes. <!-- ... --> is an HTML comment. Question: Which path does the form send card details to?

curl -s 'https://elmbridge-parkpay.example/pay?meter=P14'
echo ---
curl -s https://pay.elmbridge-council.test/

Expected output

<!doctype html>
<title>Elmbridge Parking Payments</title>
<!-- kit build [flag hidden: run the lab to find it] -->
<h1>Pay your parking charge</h1>

5. Respond and prevent

  • ☐ Remove every sticker; check all meters, not only the reported ones
  • ☐ Report the domain to the registrar and host (abuse addresses in whois) and the number to the mobile network
  • ☐ Tell residents: the council never texts a payment link; type the address yourself; call your bank if you paid
  • ☐ Prevention: tamper-evident QR plates, a short memorable payment address printed on every meter
