Data exfiltration guide

Quiet DNS

Intermediate · about 55 min

A Finance laptop at Harbourline Credit Union never touched the internet, yet a confidential file left the building. Find the DNS tunnel, measure it, and rebuild the stolen file from base32 chunks hidden in query names.

Worked exampleGuidedOn your own

11:41, Thursday 5 Nov. The SIEM at Harbourline Credit Union raised a DNS anomaly for fin-lt04, a Finance laptop. The firewall shows nothing unusual: the laptop never talked to the internet directly. You are the analyst on shift.

The evidence is in ~/case (Linux) and case/ (Python). The network tools (nmap, curl, wget, tshark, dig, nslookup, host, whois, ping, traceroute, nc, ssh, openssl, nikto, gobuster) work on a recorded copy of the case network; nothing leaves your browser.

The steps follow the incident response lifecycle: verify, scope, find the way in, preserve evidence, contain, eradicate, recover, learn. The order is based on the open LetsDefend incident response playbooks (MIT licence).

What you'll learn

  • How DNS tunnelling smuggles data out inside query names
  • Spot it by name length, unique subdomains and volume per host
  • Decode hex and base32, and rebuild a stolen file from the chunks
  • Why blocking the web is not enough when DNS goes out freely

How to use this runbook

  • Tick each - [ ] box when you have done it.
  • Stuck? Open a Hint under the step.
  • Type your answer into each check box and it tells you if you are right. Answers are short: an address, a name, a number or a time such as 09:05.
  • Write your notes under each step. Download .ipynb keeps your notes and every output.

3. Scope: who else?

Three signs of DNS tunnelling: long names, many unique names under one domain, and more queries than usual from one host. Measure all three for every client, not just the one in the alert.

  • ☐ Which client has the longest names on average?
  • ☐ Which (client, domain) pair has the most unique names?
  • ☐ Does any other machine talk to cloudmetric.example?

Hint: Normal traffic repeats the same few names. A tunnel never repeats: each chunk of data makes a new name. Question: How many different clients queried cloudmetric.example?

from collections import defaultdict

names = defaultdict(set)
lengths = defaultdict(list)
for line in open("case/dns.log"):
    f = line.split()
    client, name = f[4].split("#")[0], f[6]
    parent = ".".join(name.split(".")[-2:])
    names[(client, parent)].add(name)
    lengths[client].append(len(name))
print("client          avg name length   queries")
for c, l in sorted(lengths.items(), key=lambda x: -sum(x[1]) / len(x[1])):
    print(f"{c:15} {sum(l) / len(l):10.1f} {len(l):12}")
print()
print("most unique names under one domain:")
for (c, p), s in sorted(names.items(), key=lambda x: -len(x[1]))[:5]:
    print(f"{len(s):4}  {c:15} {p}")

7. Rebuild the stolen file

Do what the attacker's server did: collect the chunks, put them in order, drop the duplicates, join them and decode.

  • ☐ Decode the file name from hex
  • ☐ Check for missing and repeated chunks (a tunnel over UDP sometimes resends)
  • ☐ Decode the base32 and read the file. Its doc-id is the CTF flag.
  • ☐ Is this personal data? Who must be told, and by when? (see hr_contact.txt)

Hint: base32 uses only a-z and 2-7, which is why it fits in DNS names. Python's base64.b32decode wants upper case and = padding to a multiple of 8. Hint: You can decode the file name in Linux too: echo 626f6172 | xxd -r -p if your Linux has xxd. Question: How many unique data chunks were sent? Question: How many chunks were sent twice? Question: What is the name of the stolen file?

import base64
from collections import Counter

zone = ".k7q2.t.cloudmetric.example"
chunks = {}
seen = Counter()
for line in open("case/dns.log"):
    name = line.split()[6]
    if not name.endswith(zone):
        continue
    first, data = name.split(".")[0], name[: -len(zone)]
    if first == "f":
        print("file name:", bytes.fromhex(data.split(".")[1]).decode())
    elif first.isdigit():
        seq, chunk = data.split(".")
        seen[seq] += 1
        chunks[int(seq)] = chunk
print("unique chunks:", len(chunks), " sent twice:", [s for s, n in seen.items() if n > 1])
missing = [i for i in range(max(chunks) + 1) if i not in chunks]
print("missing:", missing or "none")
b32 = "".join(chunks[i] for i in sorted(chunks)).upper()
b32 += "=" * (-len(b32) % 8)
print()
print(base64.b32decode(b32).decode())
grep -o 'f\.[0-9a-f]*\.k7q2' dns.log | cut -d. -f2
echo ---
grep -o ' [0-9][0-9]\.[a-z2-7]*\.k7q2' dns.log | sort -u | sort -t. -k1,1n | cut -d. -f2 | tr -d '\n' | tr a-z A-Z > /tmp/b32
wc -c < /tmp/b32
(base32 -d /tmp/b32 2>/dev/null || echo "(no base32 here: use the Python cell above)") | head -3

8. Initial access: how did they get in?

The way in is the door you must close, or it happens again. Tick the one the evidence supports, and write the evidence next to it.

  • ☐ Phishing (a message that tricked someone)
  • ☐ Exploit of a public-facing application (a website or service bug)
  • ☐ Valid accounts (a real username and password or key, stolen or misused)
  • ☐ External remote services (VPN, remote desktop, SSH)
  • ☐ Drive-by compromise (a booby-trapped website)
  • ☐ Supply chain or trusted partner
  • ☐ Hardware added (a USB device or rogue machine)
  • ☐ Insider using access they were given
  • ☐ No intrusion (for example, traffic from outside that never got in)

9. Preserve the evidence

Cleaning up destroys evidence. Copy everything to a safe place, record the hashes and pack it before you change anything.

  • ☐ Copy the evidence and write SHA256SUMS
  • ☐ Note who collected it, when, and where it is stored (chain of custody)

Hint: Also ask for the resolver's full query log for the last 30 days: the tunnel may have run before today.

12. Fix the gaps

  • ☐ Alert in real time on long DNS names and many unique subdomains, not only on volume
  • ☐ Only the resolver may send DNS to the internet (already true here), and the resolver filters new and suspicious domains
  • ☐ Block newly registered domains (cloudmetric.example was 3 days old)
  • ☐ Stop users installing unsigned programs (application allow-listing); block search ads for software downloads
  • ☐ Keep sensitive files such as pay reviews in a protected share, not in Documents

Hint: The proxy did its job. The gap was that DNS was trusted. Which control would have stopped the tunnel at 11:09?
