Risk language: likelihood, impact, and security goals

Unit 2 · Securing Spaces · 2.1 Security Foundations: CIA Triad

Before class today. Every organization faces threats. A threat is a potential negative event (like a hard drive failing, a database leak, or a hurricane). A vulnerability is a weakness in the system that makes the threat possible (like using an outdated operating system or storing servers in a basement).

The intuition to hold onto: Hold onto this one plain fact: risk is not the same thing as threat, and the difference is the entire point of this skill. A threat is the bad thing that could happen. Risk is how much you should actually worry about it, likelihood times impact, a number you can compare against other numbers. That multiplication is what turns security from a vague sense of dread into something you can put a budget against, because a security team that tries to defend against every threat equally is a security team that has already lost the argument for resources.

A myth worth busting before we start: "We must eliminate all risk." → Impossible. Security has a cost, and organizations must accept some level of risk (known as risk appetite) to function.

Today's goal: Define likelihood, impact, and asset value in a cybersecurity context, calculate a risk score, and select and justify the most appropriate risk treatment (Mitigate, Accept, Transfer, Avoid) for a given scenario. Handout: pre-lecture-handout.docx.
