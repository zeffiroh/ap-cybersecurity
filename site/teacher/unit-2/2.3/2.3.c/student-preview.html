Security guards and layered defense-in-depth

Coding problem, 2.3.c: Defense-in-depth scorer

Skill: Mitigate Risk · Maps to: 2.3.B · Language: Python 3 (pytest)

Problem

You are auditing the physical security posture of fictional facilities for Novara Data Center. Each facility supplies a list of security layers currently in place. Each layer belongs to exactly one control category: "perimeter", "personnel", "electronic", "barrier", or "monitoring" (see atom.md, these are the five categories a sound defense-in-depth plan should draw from). A facility's depth score is the number of distinct categories represented among its layers, not the total number of layers. Two guards on patrol (both "personnel") only count once toward depth, because they do not close a new gap the way a different category would.

Implement solve(layers) that audits one facility's layer list and returns a report:

  • depth_score, count of distinct valid categories present.
  • categories_present, sorted list of the distinct valid category names present.
  • redundant_categories, dict mapping each category that has more than one layer to the count of extra layers beyond the first (e.g. 3 personnel layers -> {"personnel": 2}). Categories with only one layer are omitted.
  • recommendation, one of "STRONG", "ADEQUATE", "WEAK", based on depth_score:
  • depth_score >= 5 -> "STRONG"
  • 3 <= depth_score <= 4 -> "ADEQUATE"
  • depth_score <= 2 -> "WEAK"

Unknown/invalid category strings (anything other than the five listed above) must be ignored entirely, they do not count toward depth_score, do not appear in categories_present, and do not count toward redundant_categories.

Function contract

Implement solve(layers) in the code editor (see the Reference section below).

Input

  • layers: list[dict], each dict has:
  • "name": str, free-text description, e.g. "lobby reception guard"
  • "category": str, one of "perimeter", "personnel", "electronic", "barrier", "monitoring" (or an invalid string, which must be ignored per above)

Output

A dict with keys "depth_score" (int), "categories_present" (list[str], sorted ascending), "redundant_categories" (dict[str, int]), and "recommendation" (str).

Entry point

def solve(layers: list[dict]) -> dict

Input (layers)

list[dict] where each dict has: - "name": str, free-text label for the layer (not used in scoring logic, informational only) - "category": str, one of the five valid categories "perimeter", "personnel", "electronic", "barrier", "monitoring", or an invalid string that must be ignored.

Output (result)

A dict with exactly these keys: - "depth_score": int, number of distinct valid categories present. - "categories_present": list[str], sorted ascending, distinct valid categories present. - "redundant_categories": dict[str, int], for each valid category with more than one layer, the count of layers beyond the first in that category. Categories with exactly one layer are not included. Categories with zero layers are not included. - "recommendation": str, "STRONG" if depth_score >= 5, "ADEQUATE" if depth_score is 3 or 4, "WEAK" if depth_score is 0, 1, or 2.

Guarantees / rules

  • Pure function, deterministic, no I/O, no network. Standard library only.
  • layers may be given in any order; category counts are order-independent.
  • Invalid category strings (not one of the five valid categories) are ignored completely: they do not affect depth_score, categories_present, or redundant_categories.
  • categories_present is always sorted ascending (alphabetical).
