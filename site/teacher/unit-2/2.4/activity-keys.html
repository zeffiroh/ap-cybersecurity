Skill 2.4.a

Access logs and monitoring

Instructor notes

  • Expected flags: B-0307 (burst, 6 denials in 58 seconds), B-0205 (after-hours valid access to server-room-A at 23:41), B-0101 (location inconsistency, server-room-A at 08:45, datacenter-offsite at 00:05 next day is more than 15 hours apart so not a strict inconsistency, let students debate this one).
  • Common stumble: students flag every DENIED entry. Clarify that a single denial is noise; the threshold for a burst is 5+ failures within 60 seconds.
  • Common stumble: students miss that B-0205 at 23:41 is on the same calendar day as the 17:55 exit, walk through date arithmetic.
  • Feeds the unit project (physical intrusion timeline reconstruction) and scenario stage 2 (detecting the inside threat).
Skill 2.4.b

Alarm systems

Answer key (instructor only)

# Classification Response Reasoning
1 FALSE_ALARM none 8s since arming, inside the 45s exit delay
2 SUPPRESSED none system disarmed
3 DISPATCH (paired with row 5) monitoring center dispatches real trip, corroborated by row 5 in a different zone within the verification window
4 DISPATCH monitoring center dispatches immediately panic button bypasses arm state and verification entirely
5 DISPATCH (paired with row 3) monitoring center dispatches real trip, corroborated by row 3 within the verification window
6 FALSE_ALARM none 44s since arming, still inside the 45s exit delay (boundary is >= 45)

Instructor notes

  • Timing: rows 1, 2, 4 are unambiguous single-rule cases; rows 3/5 are the intended teaching moment for cross-zone verification, and row 6 is a deliberate off-by-one boundary case.
  • Common stumble: students treat row 4 (panic) like a normal contact sensor and check arm state or exit delay for it, push them to explain why a human-triggered duress signal is handled differently from an automated sensor trip.
  • A second common stumble: students classify rows 3 and 5 independently as LOCAL_ONLY instead of recognizing the cross-zone pairing that promotes both to DISPATCH.
  • Feeds forward to 2.4.c (motion sensors) and the unit project (designing a detection layer for a small facility).
Skill 2.4.c

Motion detectors and sensor-based detection

Instructor notes

# True detection? Reasoning
1 No, FALSE POSITIVE Sunlight is a known PIR false-positive cause; the window-adjacent sensor should be re-angled or paired with a dual-tech unit.
2 Yes, TRUE DETECTION Person cause, no competing false-positive tag.
3 No, FALSE POSITIVE HVAC airflow is a known microwave/ultrasonic false-positive cause.
4 Yes, TRUE DETECTION Both dual-tech elements independently agree the cause is a person (AND-logic satisfied).
5 No, FALSE POSITIVE Microwave element's cause (vibration) is a known false-positive tag, so AND-logic fails even though the PIR element correctly saw a person.
6 No, FALSE POSITIVE Same HVAC airflow issue as row 3, now on a PIR sensor, reinforces that placement near a vent is the root cause, not the sensor technology alone.
  • Timing: rows 2 and 4 are the unambiguous true-detection cases; rows 1, 3, 5, 6 are the intended teaching moment for false-positive causes and AND-logic.
  • Common stumble: students assume a dual-tech sensor is a true detection whenever either element reports "person", push them back to the lesson's AND-logic rule (both elements must agree).
  • Rows 1, 3, and 6 exist to reinforce that placement near a window or HVAC vent is a root cause of false positives regardless of sensor technology, the fix is often re-placement, not just tuning.
  • Feeds forward to the unit project (threat modeling a small facility) and connects to 2.4.b (alarm systems, which consume this sensor's verdict) and 2.3 (protecting physical spaces).
