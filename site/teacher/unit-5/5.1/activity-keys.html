Topic 5.1 Activity Answer Keys

Application Code Vulnerabilities · instructor-only · 4 entries

Skill 5.1.a

SQL injection

Instructor notes

  • Expected answers should highlight that prepared statements parameterize values: execute("SELECT * FROM users WHERE username = ? AND password = ?", (username, password)) rather than string concatenation.
  • Common stumble: students sometimes think input validation (like filtering ' or --) is the ultimate fix. Emphasize that parameterized queries are the mathematically sound fix, while input validation is defense-in-depth.
  • Feeds the unit project (secure database integration) and scenario.
Skill 5.1.b

Cross-site scripting (XSS)

Instructor notes

  • Expected variant labels: reflected, stored, DOM-based, tie each back to where the payload was delivered from (URL parameter vs. saved content vs. client-side script sink).
  • Common stumble: students think filtering the literal string <script> is sufficient; steer them toward onerror=, <img>, and javascript: vectors to show why escaping output beats deny-listing tags.
  • Feeds the unit project (web-app vulnerability review) and the coding problem's pattern detector.
Skill 5.1.c

API vulnerabilities

Instructor notes

  • Expected outcome: students should be able to state "check that request.user owns object_id" as the universal fix pattern.
  • Common stumble: students think a valid login token is sufficient; redirect them to the authentication-vs-authorization distinction in atom.md.
  • Feeds the unit project (API security review) and the coding problem's authorization checker.
Skill 5.1.d

Data breaches and their impact

Instructor notes

  • Expected reasoning: severity should track sensitivity of data category, then scale, then detection speed, in roughly that priority order (a small breach of very sensitive data can outrank a large breach of low-sensitivity data).
  • Common stumble: students default to "bigger record count = always worse," ignoring data sensitivity; use the health-records-vs-newsletter-emails example from atom.md to correct this.
  • Feeds the unit project (incident-response tabletop) and the coding problem's severity scorer.
