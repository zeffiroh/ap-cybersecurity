SQL injection (MODEL SOLUTION, instructor copy, do not distribute)

Coding problem, 5.1.a: Fix the Injectable Login

Skill: Mitigate Risk · Maps to: 5.1.A, 5.1.B · Language: Python 3 (pytest, sqlite3)

The situation

The authenticate function below is the login check for a small app. It works for normal users, but it builds its SQL query by concatenating the username and password straight into the query text. That is the exact flaw that makes SQL injection possible: an attacker who types SQL syntax instead of a username can change what the query means.

The starter code is the vulnerable version. Run the tests and you will see the injection cases fail: inputs like admin'-- and ' OR '1'='1 log in without the real password.

Your task

Rewrite authenticate so that user input can never change the structure of the query. Use a parameterized query (a prepared statement): pass the SQL template with ? placeholders and the user values as a separate tuple, and let the database driver bind them as data.

cur.execute("SELECT role FROM users WHERE username = ? AND password = ?", (username, password))

When you do this, the injection inputs are treated as ordinary (non-existent) usernames, so they return no row, while genuine credentials still succeed.

Function contract

Implement authenticate(users, username, password) -> str | None in the code editor: - users is a list of (username, role, password) tuples to load into an in-memory table. - Return the matching user's role if (and only if) both username and password match a row. - Return None for any failed or injected login.

Do not filter or blocklist the input, and do not compare the lists in Python. The whole point is that the database query itself must be safe. Use sqlite3 with :memory:.

A correct solution passes every test, including the injection cases. A string-concatenation version will fail them, because the injected input logs in.

Reference

Any implementation that satisfies this interface can be swapped in (reference, student, or composite) and must pass the tests unchanged.

Entry point

def authenticate(users: list[tuple[str, str, str]], username: str, password: str) -> str | None

Input

  • users: a list of (username, role, password) rows to load into an in-memory table.
  • username, password: the submitted login credentials (untrusted input).

Output

  • The matching user's role (a string) when a row's username AND password both equal the submitted values.
  • None when no row matches, including every injection attempt.

Guarantees / rules

  • Deterministic, no network. Standard library only (sqlite3).
  • The username/password comparison must be performed by a SQL query, using a parameterized statement with ? placeholders and the values bound separately.
  • No input filtering, blocklisting, or Python-side list comparison.

Acceptance

Your code passes when every test below shows a checkmark (some are hidden until you run them). the query is parameterized rather than built by string concatenation.

# Reference solution import sqlite3 def authenticate(users, username, password): """ Parameterized login: the SQL template is fixed and the user values are bound separately as data, so injected SQL syntax is treated as an ordinary (and non-existent) username rather than as part of the query structure. """ conn = sqlite3.connect(":memory:") cur = conn.cursor() cur.execute("CREATE TABLE users (username TEXT, role TEXT, password TEXT)") cur.executemany("INSERT INTO users VALUES (?, ?, ?)", users) cur.execute( "SELECT role FROM users WHERE username = ? AND password = ?", (username, password), ) row = cur.fetchone() conn.close() return row[0] if row else None
