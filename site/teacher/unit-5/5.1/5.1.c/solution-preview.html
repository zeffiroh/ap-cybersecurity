1. Brief

The situation. Build the server-side authorization check an API gateway should run before returning an object. Given the authenticated caller's user id, the id of the object they are requesting, an object-ownership map, and the caller's role, decide whether the request is allowed.

Rules: - A request is allowed if the caller owns the requested object (the object's owner equals the caller's user_id), OR the caller's role is "admin". - A request is denied (a BOLA violation) if the object exists but the caller neither owns it nor is an admin. - A request for an object id that does not exist in the ownership map is denied with reason "not_found".

Lesson objective. Explain how broken object-level authorization (BOLA/IDOR) and excessive-data-exposure flaws let an attacker abuse an application programming interface (API) to access data or objects they should not be able to reach, and can identify the missing check that causes it.

What comes in

  • request: {"user_id": str, "role": str, "object_id": str}
  • ownership: dict mapping object_id -> owner user_id (e.g. {"482": "u1", "483": "u2"})

What must come out

A dict: {"allowed": bool, "reason": str} where reason is one of "owner", "admin", "not_owner", "not_found".

<details><summary>Reference: the exact contract</summary>

Any implementation that satisfies this interface can be swapped in (reference, student, or composite) and must pass the tests unchanged.

Entry point

def solve(request: dict, ownership: dict) -> dict

Input

  • request: {"user_id": str, "role": str, "object_id": str}, the authenticated caller and the object they are requesting.
  • ownership: dict[str, str] mapping object_id -> owner user_id.

Output (result)

{"allowed": bool, "reason": str} where reason is exactly one of: - "owner": caller's user_id matches the object's owner. - "admin": caller's role is "admin" (allowed regardless of ownership). - "not_owner": object exists but caller neither owns it nor is admin. - "not_found", object_id is not a key in ownership.

Guarantees / rules

  • Pure function, deterministic, no I/O, no network. Standard library only.
  • Ownership check takes priority: if the caller owns the object, reason is "owner" even if role is also "admin".
  • "not_found" is checked independently of role/ownership, a missing object is always denied.

Acceptance

3. Build it

This is the model solution.

  • [ ] solve handles the worked examples
  • [ ] solve handles your edge cases
from typing import Dict def solve(request: Dict[str, str], ownership: Dict[str, str]) -> Dict[str, object]: object_id = request.get("object_id") user_id = request.get("user_id") role = request.get("role") if object_id not in ownership: return {"allowed": False, "reason": "not_found"} owner = ownership[object_id] if owner == user_id: return {"allowed": True, "reason": "owner"} if role == "admin": return {"allowed": True, "reason": "admin"} return {"allowed": False, "reason": "not_owner"}
