Coding problem, 5.4.a: RSA key-pair parameters

Skill: Mitigate Risk · Maps to: 5.4.A · Language: Python 3 (pytest)

Problem

Before RSA can encrypt or sign anything, it needs a key pair. Given two prime numbers p and q, implement the first steps of RSA key generation described in atom.md: compute the modulus n, compute phi(n), and validate whether a proposed public/private exponent pair (e, d) actually satisfies the required mathematical relationship.

Function contract

Implement, in the code editor: - rsa_params(p: int, q: int) -> tuple, given two (small, distinct) primes, return (n, phi_n) where n = p * q and phi_n = (p - 1) * (q - 1). - is_valid_keypair(e: int, d: int, phi_n: int) -> bool, return True iff (e * d) % phi_n == 1, i.e. d is the modular inverse of e mod phi_n. - solve(data: dict) -> dict, the blackbox entry point that dispatches to the two functions above (see the Reference section below).

The math (see atom.md)

n       = p * q
phi(n)  = (p - 1) * (q - 1)
valid keypair (e, d)  <=>  (e * d) mod phi(n) == 1

The public key is (e, n); the private key is (d, n). Both share n, but d cannot be recovered from e and n alone without knowing phi(n) (which requires factoring n back into p and q).

Input / Output

  • rsa_params(p, q): p, q: int (primes) -> (n, phi_n) tuple of int.
  • is_valid_keypair(e, d, phi_n): all int -> bool.
  • solve(data): data = {"op": "params", "p": <int>, "q": <int>} -> {"n": <int>, "phi_n": <int>}, or data = {"op": "validate", "e": <int>, "d": <int>, "phi_n": <int>} -> {"valid": <bool>}.

Examples

rsa_params(3, 11)  -> (33, 20)     # n = 3*11 = 33, phi(n) = 2*10 = 20
rsa_params(5, 11)  -> (55, 40)     # n = 5*11 = 55, phi(n) = 4*10 = 40

is_valid_keypair(e=3, d=7, phi_n=20)  -> True   # 3*7 = 21, 21 % 20 == 1
is_valid_keypair(e=3, d=6, phi_n=20)  -> False  # 3*6 = 18, 18 % 20 != 1

Constraints

  • Deterministic, offline, standard library only. No external crypto/bignum libraries, this problem implements the underlying arithmetic directly.
  • Inputs are small, textbook-scale integers as in the atom's worked examples; no primality checking is required.
  • Must pass all cases in the tests (visible + hidden), including the p=3,q=11 and p=5,q=11 examples from atom.md, and both valid and invalid keypair checks.

Reference

Any implementation that satisfies this interface can be swapped in (reference, student, or composite) and must pass the tests unchanged.

Entry points

def rsa_params(p: int, q: int) -> tuple
def is_valid_keypair(e: int, d: int, phi_n: int) -> bool
def solve(data: dict) -> dict

solve() is the blackbox entry point; rsa_params() and is_valid_keypair() are the underlying primitives it's built on and are tested directly as well.

Input

  • rsa_params(p, q): p and q are (small, distinct) prime integers.
  • is_valid_keypair(e, d, phi_n): e, d, phi_n are all int.
  • solve(data): data is a dict with "op" equal to "params" or "validate".
  • "params": {"op": "params", "p": <int>, "q": <int>}
  • "validate": {"op": "validate", "e": <int>, "d": <int>, "phi_n": <int>}

Output (result)

  • rsa_params(p, q) returns a 2-tuple (n, phi_n) where n = p * q and phi_n = (p - 1) * (q - 1).
  • is_valid_keypair(e, d, phi_n) returns bool: True iff (e * d) % phi_n == 1.
  • solve(...) returns {"n": <int>, "phi_n": <int>} for op "params", or {"valid": <bool>} for op "validate".

Guarantees / rules

  • Pure functions, deterministic, no I/O, no network. Standard library only, no external crypto/bignum libraries; this is the from-scratch pedagogical RSA-parameter math described in atom.md (n = pq, phi(n) = (p-1)(q-1), ed ≡ 1 mod phi(n)).
  • Inputs are small, textbook-scale integers (not cryptographically secure primes); no primality checking is required inside rsa_params, callers are trusted to pass primes.
  • is_valid_keypair must work for any nonnegative e, d, phi_n combination, including cases where the pair is deliberately invalid (used to test rejection).
