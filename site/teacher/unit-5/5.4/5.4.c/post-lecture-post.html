Hold onto the three guarantees (authenticity, integrity, non-repudiation) as a set, because 5.4.d is about to show you the one gap none of this solves on its own: even a perfect signature only proves the person who holds a particular private key signed something, it says nothing about whether that person is who they claim to be. Key terms to lock in: - Digital signature, a value computed from a message digest and a private key that lets anyone with the matching public key verify the message's authenticity and integrity. - Signing, computing signature = hash(message)^d mod n with the signer's private exponent. - Verification, recomputing hash(message) and comparing it to signature^e mod n, computed with the signer's public exponent. - Authenticity, assurance that a message originated from the claimed sender. - Non-repudiation, the signer cannot plausibly deny having signed, since only they hold the private key; a property HMAC (shared-secret) schemes cannot provide. - Message digest, the fixed-size hash output that is actually signed, rather than signing the raw message.

Common misconceptions -- don't fall for these: - "A digital signature encrypts the message for confidentiality." → It does not provide secrecy at all; the message is often sent in the clear alongside the signature. Signing proves authenticity and integrity, not confidentiality, that requires separately encrypting with the recipient's public key (5.4.a). - "HMAC and digital signatures provide the same guarantees." → Both give integrity and authenticity, but only digital signatures give non-repudiation, because HMAC's shared secret means either party could have produced a valid tag. - "You sign the message directly with RSA." → Real schemes hash the message first and sign the fixed-size digest, both for performance and to avoid structural weaknesses in signing large raw inputs directly. - "If verification succeeds, the message was never read by anyone else in transit." → Verification proves integrity and authenticity, not secrecy; an unencrypted signed message can still be read by anyone who intercepts it.

**Key terms to lock in:**
- **Digital signature**, a value computed from a message digest and a private key that lets anyone with the matching public key verify the message's authenticity and integrity.
- **Signing**, computing `signature = hash(message)^d mod n` with the signer's private exponent.
- **Verification**, recomputing `hash(message)` and comparing it to `signature^e mod n`, computed with the signer's public exponent.
- **Authenticity**, assurance that a message originated from the claimed sender.
- **Non-repudiation**, the signer cannot plausibly deny having signed, since only they hold the private key; a property HMAC (shared-secret) schemes cannot provide.
- **Message digest**, the fixed-size hash output that is actually signed, rather than signing the raw message.

**Common misconceptions -- don't fall for these:**
- "A digital signature encrypts the message for confidentiality." → It does not provide secrecy at all; the message is often sent in the clear alongside the signature. Signing proves authenticity and integrity, not confidentiality, that requires separately encrypting with the recipient's public key (5.4.a).
- "HMAC and digital signatures provide the same guarantees." → Both give integrity and authenticity, but only digital signatures give non-repudiation, because HMAC's shared secret means either party could have produced a valid tag.
- "You sign the message directly with RSA." → Real schemes hash the message first and sign the fixed-size digest, both for performance and to avoid structural weaknesses in signing large raw inputs directly.
