1. Brief

The situation. A browser has just received a TLS certificate chain from a server: a leaf (end-entity) certificate and one or more issuing CA certificates, and it needs to decide whether to trust it. Real browsers call into a full X.509 library to do this; you are going to implement the validation logic itself, the same logic that library runs under the hood, using the small-number RSA sign/verify math from 5.4.b/5.4.c.

Each certificate is a plain dict:

{
  "subject": "www.meridianbank.example",     # who this certificate identifies
  "issuer": "Meridian Intermediate CA",       # who issued (signed) it
  "public_key": [17, 2501],                   # [e, n] -- this cert's own public key
  "signature": 1271,                          # issuer's signature over this cert's fields
  "not_before": 1000,                         # validity window, integer "time units"
  "not_after": 9000,
  "revoked": False,
}

A chain is a list of these dicts ordered leaf-first: [leaf, intermediate..., root]. The last entry is claimed to be a root CA certificate (self-signed: its own issuer equals its own subject).

Lesson objective. Explain what a digital certificate contains and why, describe how a client walks a certificate chain up to a trusted root to decide whether to trust a public key, and identify why and how certificates get revoked before their stated expiration.

<details><summary>Reference: the exact contract</summary>

Any implementation that satisfies this interface can be swapped in (reference, student, or composite) and must pass the tests unchanged.

Entry points

def compute_digest(cert: dict) -> int
def rsa_sign(digest: int, d: int, n: int) -> int
def rsa_verify(digest: int, signature: int, e: int, n: int) -> bool
def validate_chain(chain: list, trusted_roots: dict, current_time: int) -> dict
def solve(data: dict) -> dict

solve() is the blackbox entry point; the other functions are the underlying primitives it is built on and are tested directly as well.

Input

  • compute_digest(cert): cert is a dict with keys subject (str), issuer (str), public_key ([e, n] list of two int), not_before (int), not_after (int). (signature and revoked may also be present but are not part of the digest.)
  • rsa_sign(digest, d, n) / rsa_verify(digest, signature, e, n): all int.
  • validate_chain(chain, trusted_roots, current_time):
  • chain: list[dict], leaf-first, each dict shaped like cert above plus signature (int, the issuer's signature over compute_digest(cert)) and revoked (bool).
  • trusted_roots: dict[str, list[int]] mapping a trusted root CA's subject name to its known [e, n] public key (the local trust store).
  • current_time: int.
  • solve(data): data is a dict with "op" equal to "validate" or "digest".
  • "validate": {"op": "validate", "chain": [...], "trusted_roots": {...}, "current_time": int}
  • "digest": {"op": "digest", "cert": {...}}

Output (result)

  • compute_digest(...) returns an int.
  • rsa_sign(...) returns an int.
  • rsa_verify(...) returns bool.
  • validate_chain(...) returns {"valid": bool, "reason": str}, where reason is one of "valid", "expired", "revoked", "broken_chain", "untrusted_root", "bad_signature".
  • solve(...) returns validate_chain(...)'s dict for op "validate", or {"digest": int} for op "digest".

Guarantees / rules

  • Pure functions, deterministic, no I/O, no network. Standard library only -- no cryptography, ssl, or hashlib; this is a from-scratch textbook-RSA exercise, not a real X.509 parser.
  • compute_digest canonicalizes as f"{subject}|{issuer}|{e}:{n}|{not_before}|{not_after}" and reduces with the rolling hash h = (h * 131 + ord(ch)) % (2**61 - 1) over every character.
  • validate_chain walks the chain leaf-first (index 0) to root (last index) and, for each certificate, checks in this order: validity window, revocation, issuer/subject chain linkage (or trusted-root membership for the last certificate), then signature -- returning the first failure encountered.
  • The public key used to verify a non-root certificate's signature is always the next certificate's public_key, never the certificate's own key. The public key used to verify the root's self-signature is always looked up from trusted_roots, never trusted from the chain data itself.
  • A self-signed certificate whose subject is absent from trusted_roots is "untrusted_root", even if its own signature verifies correctly.

Acceptance

Your code passes when every test below shows a checkmark (some are hidden until you run them).

3. Build it

from typing import Any _MODULUS = (2 ** 61) - 1 def compute_digest(cert: dict) -> int: e, n = cert["public_key"] canonical = f'{cert["subject"]}|{cert["issuer"]}|{e}:{n}|{cert["not_before"]}|{cert["not_after"]}' h = 0 for ch in canonical: h = (h * 131 + ord(ch)) % _MODULUS return h def rsa_sign(digest: int, d: int, n: int) -> int: return pow(digest % n, d, n) def rsa_verify(digest: int, signature: int, e: int, n: int) -> bool: return pow(signature, e, n) == digest % n def validate_chain(chain: list, trusted_roots: dict, current_time: int) -> dict: for i, cert in enumerate(chain): if current_time < cert["not_before"] or current_time > cert["not_after"]: return {"valid": False, "reason": "expired"} if cert.get("revoked", False): return {"valid": False, "reason": "revoked"} if i + 1 < len(chain): issuer_cert = chain[i + 1] if cert["issuer"] != issuer_cert["subject"]: return {"valid": False, "reason": "broken_chain"} issuer_pubkey = issuer_cert["public_key"] else: root_key = trusted_roots.get(cert["subject"]) if root_key is None or list(root_key) != list(cert["public_key"]): return {"valid": False, "reason": "untrusted_root"} issuer_pubkey = root_key digest = compute_digest(cert) e, n = issuer_pubkey if not rsa_verify(digest, cert["signature"], e, n): return {"valid": False, "reason": "bad_signature"} return {"valid": True, "reason": "valid"} def solve(data: Any) -> Any: op = data["op"] if op == "validate": return validate_chain(data["chain"], data["trusted_roots"], data["current_time"]) elif op == "digest": return {"digest": compute_digest(data["cert"])} else: raise ValueError(f"unknown op: {op!r}")
