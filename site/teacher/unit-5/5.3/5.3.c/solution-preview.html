Coding problem, 5.3.c: Implement HMAC-SHA256 by hand

Skill: Mitigate Risk · Maps to: 5.3.B, 5.3.C · Language: Python 3 (pytest)

Problem

An API needs to verify that requests were sent by a client holding a shared secret key, and that the request body wasn't tampered with in transit. Rather than calling Python's built-in hmac module, build the FIPS 198-1 HMAC construction yourself on top of hashlib.sha256, so you can see exactly how the ipad/opad key-nesting defeats length-extension attacks.

Function contract

Implement, in the code editor: - hmac_sha256(key: bytes, message: bytes) -> str, return the HMAC-SHA256 tag as a lowercase 64-character hex string. - verify(key: bytes, message: bytes, tag: str) -> bool, recompute the tag and compare it (case-insensitively) to the given tag using a constant-time comparison. - solve(data: dict) -> dict, the blackbox entry point that dispatches to the two functions above (see the Reference section below).

You must implement the ipad/opad key derivation and the double-nested hashing yourself. You may use hashlib.sha256 only as the inner hash primitive H(), do not import the hmac module for the core logic.

The construction (FIPS 198-1)

HMAC(key, message) = H( (key XOR opad) || H( (key XOR ipad) || message ) )
  • Block size for SHA-256 is 64 bytes.
  • If key is longer than 64 bytes, replace it with H(key) first.
  • Right-pad key with 0x00 bytes up to exactly 64 bytes -> call this k0.
  • ipad = the byte 0x36 repeated 64 times; opad = the byte 0x5c repeated 64 times.
  • inner_key = k0 XOR ipad, outer_key = k0 XOR opad (byte-wise XOR).
  • inner_hash = H(inner_key || message)
  • final tag = H(outer_key || inner_hash), hex-encoded.

Input / Output

  • hmac_sha256(key, message): key: bytes, message: bytes -> hex str tag.
  • verify(key, message, tag): tag: str (hex, any case) -> bool.
  • solve(data): data = {"op": "tag", "key": "<hex>", "message": "<str>"} -> {"tag": "<hex>"}, or data = {"op": "verify", "key": "<hex>", "message": "<str>", "tag": "<hex>"} -> {"valid": <bool>}.

Examples

hmac_sha256(b"secretkey", b"transfer $100 to acct 42")
  -> "5b1f9a2c...b3" (64 hex chars; must match Python's hmac.new(key, msg, sha256).hexdigest())

verify(b"secretkey", b"transfer $100 to acct 42", "5b1f9a2c...b3") -> True
verify(b"secretkey", b"transfer $900 to acct 42", "5b1f9a2c...b3") -> False  # tampered message

Constraints

  • Deterministic, offline, standard library only (hashlib only, no hmac module).
  • Correctness is checked against Python's own hmac module inside the tests (used there only as an independent oracle, not as part of your implementation).
  • Must pass all cases in the tests (visible + hidden), including empty keys/messages, keys longer than the 64-byte block size, and case-insensitive tag comparison in verify().

Reference

Entry points

def hmac_sha256(key: bytes, message: bytes) -> str
def verify(key: bytes, message: bytes, tag: str) -> bool
def solve(data: dict) -> dict

solve() is the blackbox entry point; hmac_sha256() and verify() are the underlying primitives it's built on and are tested directly as well.

Input

  • hmac_sha256(key, message): key and message are raw bytes of any length (including empty and longer-than-block-size keys).
  • verify(key, message, tag): same key/message as above; tag is a hex string (may be upper or lower case) claiming to be the correct HMAC-SHA256 tag.
  • solve(data): data is a dict with "op" equal to "tag" or "verify".
  • "tag": {"op": "tag", "key": <hex str>, "message": <str>}
  • "verify": {"op": "verify", "key": <hex str>, "message": <str>, "tag": <hex str>}
  • key arrives as a hex string (decode with bytes.fromhex); message arrives as a plain UTF-8 string (encode with .encode("utf-8")).

Output (result)

  • hmac_sha256(...) returns a lowercase hex string (64 hex characters for SHA-256).
  • verify(...) returns bool.
  • solve(...) returns {"tag": <hex str>} for op "tag", or {"valid": <bool>} for op "verify".

Guarantees / rules

  • Pure functions, deterministic, no I/O, no network. Standard library only (hashlib.sha256 may be used as the inner hash primitive H(); the ipad/opad key derivation and double-nesting must be implemented directly, not via the hmac module).
  • Must implement the FIPS 198-1 HMAC construction: HMAC(key, message) = H((key XOR opad) || H((key XOR ipad) || message)), with ipad = 0x36 and opad = 0x5c repeated to the 64-byte SHA-256 block size, and keys longer than the block size first hashed down with H() before padding.
  • Any single-bit change to message or key must produce a different tag.
  • verify() must accept tags regardless of hex case (upper/lower).

# Reference solution """Reference solution for 5.3.c. MUST pass 100% of the tests. Also the default 'blackbox' implementation students can swap out (see the hidden grading tests). Implements the FIPS 198-1 HMAC construction by hand (ipad/opad nesting) on top of hashlib.sha256, used only as the inner H() step. Crypto problems implement the underlying math/logic directly rather than calling hmac.*. """ import hashlib BLOCK_SIZE = 64 # SHA-256 block size in bytes IPAD = 0x36 OPAD = 0x5C def _h(data: bytes) -> bytes: """The inner hash primitive H(). Only stdlib hashlib.sha256 is used here.""" return hashlib.sha256(data).digest() def _derive_key(key: bytes) -> bytes: """Normalize key to exactly BLOCK_SIZE bytes per FIPS 198-1: hash keys longer than the block size, right-pad shorter keys with zero bytes.""" if len(key) > BLOCK_SIZE: key = _h(key) return key + b"\x00" * (BLOCK_SIZE - len(key)) def _xor_bytes(data: bytes, pad: int) -> bytes: return bytes(b ^ pad for b in data) def hmac_sha256(key: bytes, message: bytes) -> str: """Compute HMAC-SHA256(key, message) and return the tag as a lowercase hex string. HMAC(key, message) = H( (key XOR opad) || H( (key XOR ipad) || message ) ) """ k0 = _derive_key(key) inner_key = _xor_bytes(k0, IPAD) outer_key = _xor_bytes(k0, OPAD) inner_hash = _h(inner_key + message) tag = _h(outer_key + inner_hash) return tag.hex() def _constant_time_equal(a: str, b: str) -> bool: """Compare two equal-or-unequal-length strings without short-circuiting on the first mismatch, to avoid leaking timing information about where tags differ.""" if len(a) != len(b): return False result = 0 for ca, cb in zip(a, b): result |= ord(ca) ^ ord(cb) return result == 0 def verify(key: bytes, message: bytes, tag: str) -> bool: """Return True iff `tag` is the correct HMAC-SHA256 tag for (key, message).""" expected = hmac_sha256(key, message) return _constant_time_equal(expected, tag.lower()) def solve(data: dict) -> dict: """Blackbox entry point. Dispatches on data['op']: - {"op": "tag", "key": <hex str>, "message": <str>} -> {"tag": <hex str>} - {"op": "verify", "key": <hex str>, "message": <str>, "tag": <hex str>} -> {"valid": <bool>} Keys and messages are given as UTF-8 strings; `key` is provided as a hex string to allow arbitrary binary-looking keys through a JSON-friendly interface. """ op = data["op"] key = bytes.fromhex(data["key"]) message = data["message"].encode("utf-8") if op == "tag": return {"tag": hmac_sha256(key, message)} elif op == "verify": return {"valid": verify(key, message, data["tag"])} else: raise ValueError(f"unknown op: {op!r}")
