1. Brief

The situation. An API needs to verify that requests were sent by a client holding a shared secret key, and that the request body wasn't tampered with in transit. Rather than calling Python's built-in hmac module, build the FIPS 198-1 HMAC construction yourself on top of hashlib.sha256, so you can see exactly how the ipad/opad key-nesting defeats length-extension attacks.

Lesson objective. Explain why a plain hash cannot prove who sent a message, describe how HMAC combines a secret key with a hash function to provide both integrity and authenticity, and classify a given integrity-check design as secure or vulnerable to tampering.

<details><summary>Reference: the exact contract</summary>

Any implementation that satisfies this interface can be swapped in (reference, student, or composite) and must pass the tests unchanged.

Entry points

def hmac_sha256(key: bytes, message: bytes) -> str
def verify(key: bytes, message: bytes, tag: str) -> bool
def solve(data: dict) -> dict

solve() is the blackbox entry point; hmac_sha256() and verify() are the underlying primitives it's built on and are tested directly as well.

Input

  • hmac_sha256(key, message): key and message are raw bytes of any length (including empty and longer-than-block-size keys).
  • verify(key, message, tag): same key/message as above; tag is a hex string (may be upper or lower case) claiming to be the correct HMAC-SHA256 tag.
  • solve(data): data is a dict with "op" equal to "tag" or "verify".
  • "tag": {"op": "tag", "key": <hex str>, "message": <str>}
  • "verify": {"op": "verify", "key": <hex str>, "message": <str>, "tag": <hex str>}
  • key arrives as a hex string (decode with bytes.fromhex); message arrives as a plain UTF-8 string (encode with .encode("utf-8")).

Output (result)

  • hmac_sha256(...) returns a lowercase hex string (64 hex characters for SHA-256).
  • verify(...) returns bool.
  • solve(...) returns {"tag": <hex str>} for op "tag", or {"valid": <bool>} for op "verify".

Guarantees / rules

  • Pure functions, deterministic, no I/O, no network. Standard library only (hashlib.sha256 may be used as the inner hash primitive H(); the ipad/opad key derivation and double-nesting must be implemented directly, not via the hmac module).
  • Must implement the FIPS 198-1 HMAC construction: HMAC(key, message) = H((key XOR opad) || H((key XOR ipad) || message)), with ipad = 0x36 and opad = 0x5c repeated to the 64-byte SHA-256 block size, and keys longer than the block size first hashed down with H() before padding.
  • Any single-bit change to message or key must produce a different tag.
  • verify() must accept tags regardless of hex case (upper/lower).

Acceptance

Your code passes when every test below shows a checkmark (some are hidden until you run them).

3. Build it

This is the model solution.

  • [ ] solve handles your edge cases
import hashlib BLOCK_SIZE = 64 IPAD = 0x36 OPAD = 0x5C def _h(data: bytes) -> bytes: return hashlib.sha256(data).digest() def _derive_key(key: bytes) -> bytes: if len(key) > BLOCK_SIZE: key = _h(key) return key + b"\x00" * (BLOCK_SIZE - len(key)) def _xor_bytes(data: bytes, pad: int) -> bytes: return bytes(b ^ pad for b in data) def hmac_sha256(key: bytes, message: bytes) -> str: k0 = _derive_key(key) inner_key = _xor_bytes(k0, IPAD) outer_key = _xor_bytes(k0, OPAD) inner_hash = _h(inner_key + message) tag = _h(outer_key + inner_hash) return tag.hex() def _constant_time_equal(a: str, b: str) -> bool: if len(a) != len(b): return False result = 0 for ca, cb in zip(a, b): result |= ord(ca) ^ ord(cb) return result == 0 def verify(key: bytes, message: bytes, tag: str) -> bool: expected = hmac_sha256(key, message) return _constant_time_equal(expected, tag.lower()) def solve(data: dict) -> dict: op = data["op"] key = bytes.fromhex(data["key"]) message = data["message"].encode("utf-8") if op == "tag": return {"tag": hmac_sha256(key, message)} elif op == "verify": return {"valid": verify(key, message, data["tag"])} else: raise ValueError(f"unknown op: {op!r}")
