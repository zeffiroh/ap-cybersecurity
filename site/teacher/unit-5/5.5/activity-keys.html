Topic 5.5 Activity Answer Keys

Secure Web Application Design · instructor-only · 3 entries

Skill 5.5.a

Input validation and sanitization

Instructor notes

  • Expected outcome: students discover that a rule stated only in terms of "reject bad stuff" (denylist thinking) keeps needing patches, while a rule stated as "accept only this exact shape" (allowlist thinking) closes whole classes of bypass at once.
  • Common stumble: students propose denylist rules first (e.g. "reject anything with a quote mark"); prompt them to restate the rule as a positive shape (regex-like) instead.
  • Feeds the coding problem's field validator and the sim's SAFE/BLOCKED classification task.
Skill 5.5.b

Secure coding practices

Instructor notes

  • Expected reasoning: students should connect each violation to the specific attack it enables (concatenated SQL -> injection; verbose errors -> reconnaissance; root process -> full compromise on exploit).
  • Common stumble: students propose "add input validation" as a universal fix even when the real issue is a query-building pattern or a privilege setting that validation cannot touch.
  • Feeds the coding problem's configuration auditor and the sim's PASS/FLAG review task.
Skill 5.5.c

Application security testing (SAST/DAST)

Instructor notes

  • Expected reasoning: "does this require the app to be running?" separates SAST from DAST; "does this require knowing what the correct business behavior should be?" separates automated tooling from human pentesting.
  • Common stumble: students assume a clean SAST/DAST scan means "no vulnerabilities", remind them both tools only find what they are built to look for.
  • Feeds the coding problem's SAST rule engine and the sim's classification task.
