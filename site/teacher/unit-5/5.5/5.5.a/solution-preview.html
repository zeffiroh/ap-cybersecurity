1. Brief

The situation. Build the server-side validation gate described in the lesson: given a batch of submitted form field values, classify each as SAFE or BLOCKED using allowlist rules per field type plus detection of known injection meta-characters/keywords, the same two checks a real input-validation layer runs before any value reaches a database query, HTML page, or shell.

Lesson objective. Explain why every application must treat user input as untrusted, distinguish allowlist from denylist validation, describe where validation must occur to be trustworthy, and identify how input validation prevents injection classes like SQL injection, cross-site scripting, and command injection.

What comes in

submissions: list[dict], each {"field": str, "type": str, "value": str}. type is one of "zip", "email", "quantity", "username".

What must come out

list[str] of the values that are BLOCKED, in the same order they appeared in the input.

<details><summary>Reference: the exact contract</summary>

Any implementation that satisfies this interface can be swapped in (reference, student, or composite) and must pass the tests unchanged.

Entry point

def solve(submissions: list) -> list

Input (submissions)

list[dict], each {"field": str, "type": str, "value": str}. type is one of "zip", "email", "quantity", "username".

Output (result)

list[str], the value of every submission that is BLOCKED, in the same order as the input. A submission is blocked if either condition holds: 1. Its value fails the allowlist pattern for its type (server-side shape check). 2. Its value matches a known injection meta-character/keyword signature (checked independently of type, a value can match the type's shape and still be blocked).

Allowlist rules

  • zip: exactly 5 digits.
  • email: local@domain.tld shape (letters/digits/._+- local part, dotted domain).
  • quantity: integer string from 1 to 99 inclusive (no leading zero, no 0, no 100+).
  • username: 3-20 characters, letters/digits/underscore only.

Guarantees / rules

  • Pure function, deterministic, no I/O, no network. Standard library only.
  • Injection signatures include (case-insensitive): --, ;, <script, UNION SELECT, OR 1=1, ' OR ', DROP TABLE, ../ path traversal, and URL-encoded %3B/%2F.

Acceptance

Your code passes when every test below shows a checkmark (some are hidden until you run them).

3. Build it

This is the model solution.

import re from typing import Dict, List _ALLOW = { "zip": re.compile(r"^\d{5}$"), "email": re.compile(r"^[A-Za-z0-9._+-]+@[A-Za-z0-9-]+\.[A-Za-z0-9.-]+$"), "quantity": re.compile(r"^(?:[1-9][0-9]?)$"), "username": re.compile(r"^[A-Za-z0-9_]{3,20}$"), } _INJECTION = re.compile( r"(--|;|<script|</script|UNION\s+SELECT|OR\s+1\s*=\s*1|'\s*OR\s*'|\bDROP\s+TABLE\b|" r"\.\./|%3B|%2F)", re.IGNORECASE, ) def solve(submissions: List[Dict[str, str]]) -> List[str]: blocked = [] for sub in submissions: field_type = sub["type"] value = sub["value"] pattern = _ALLOW.get(field_type) allow_ok = bool(pattern and pattern.match(value)) has_injection = bool(_INJECTION.search(value)) if not allow_ok or has_injection: blocked.append(value) return blocked
