Coding problem, 5.5.a: Field validator (allowlist + injection detector)

Skill: Mitigate Risk · Maps to: 5.5.A · Language: Python 3 (pytest)

Problem

Build the server-side validation gate described in the lesson: given a batch of submitted form field values, classify each as SAFE or BLOCKED using allowlist rules per field type plus detection of known injection meta-characters/keywords, the same two checks a real input-validation layer runs before any value reaches a database query, HTML page, or shell.

Function contract

Implement solve(submissions: list) -> list in the code editor (see the Reference section below).

Input

submissions: list[dict], each {"field": str, "type": str, "value": str}. type is one of "zip", "email", "quantity", "username".

Output

list[str] of the values that are BLOCKED, in the same order they appeared in the input.

Allowlist rules (per type)

  • zip: exactly 5 digits.
  • email: local@domain.tld shape.
  • quantity: integer string 1-99.
  • username: 3-20 letters/digits/underscore.

A value is also BLOCKED (even if it matches the allowlist shape) if it contains a known injection signature: --, ;, <script, UNION SELECT, OR 1=1, ' OR ', DROP TABLE, ../, %3B, %2F (case-insensitive).

Examples

[{"field":"zip","type":"zip","value":"94107"}]                    ->  []
[{"field":"zip","type":"zip","value":"9410"}]                     ->  ["9410"]
[{"field":"u","type":"username","value":"admin'--"}]               ->  ["admin'--"]

Constraints

  • Deterministic, offline, standard library only.
  • Must pass all cases in the tests (visible + hidden).

Entry point

def solve(submissions: list) -> list

Input (submissions)

list[dict], each {"field": str, "type": str, "value": str}. type is one of "zip", "email", "quantity", "username".

Output (result)

list[str], the value of every submission that is BLOCKED, in the same order as the input. A submission is blocked if either condition holds: 1. Its value fails the allowlist pattern for its type (server-side shape check). 2. Its value matches a known injection meta-character/keyword signature (checked independently of type, a value can match the type's shape and still be blocked).

Allowlist rules

  • zip: exactly 5 digits.
  • email: local@domain.tld shape (letters/digits/._+- local part, dotted domain).
  • quantity: integer string from 1 to 99 inclusive (no leading zero, no 0, no 100+).
  • username: 3-20 characters, letters/digits/underscore only.

Guarantees / rules

  • Pure function, deterministic, no I/O, no network. Standard library only.
  • Injection signatures include (case-insensitive): --, ;, <script, UNION SELECT, OR 1=1, ' OR ', DROP TABLE, ../ path traversal, and URL-encoded %3B/%2F.

# Reference solution """Reference solution for 5.5.a. MUST pass 100% of the tests. Also the default 'blackbox' implementation students can swap out (see the hidden grading tests).""" import re from typing import Dict, List # Allowlist patterns per field type (server-side rules — see atom.md). _ALLOW = { "zip": re.compile(r"^\d{5}$"), "email": re.compile(r"^[A-Za-z0-9._+-]+@[A-Za-z0-9-]+\.[A-Za-z0-9.-]+$"), "quantity": re.compile(r"^(?:[1-9][0-9]?)$"), # 1-99 "username": re.compile(r"^[A-Za-z0-9_]{3,20}$"), } # Known injection meta-character / keyword signatures, checked regardless of type. _INJECTION = re.compile( r"(--|;|<script|</script|UNION\s+SELECT|OR\s+1\s*=\s*1|'\s*OR\s*'|\bDROP\s+TABLE\b|" r"\.\./|%3B|%2F)", re.IGNORECASE, ) def solve(submissions: List[Dict[str, str]]) -> List[str]: """Classify each submission; return the `value`s that are BLOCKED, in input order. A submission is BLOCKED if its value fails the type's allowlist pattern, or if it contains a known injection meta-character/keyword signature (checked independent of type). """ blocked = [] for sub in submissions: field_type = sub["type"] value = sub["value"] pattern = _ALLOW.get(field_type) allow_ok = bool(pattern and pattern.match(value)) has_injection = bool(_INJECTION.search(value)) if not allow_ok or has_injection: blocked.append(value) return blocked
