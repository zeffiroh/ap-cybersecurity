Problem

In a Zero Trust Network Architecture (ZTNA), network access is never implicitly granted based on a user's location. Instead, every request to access a corporate resource must be explicitly authenticated, authorized, and checked for health compliance.

You are tasked with implementing the evaluation logic for a Zero Trust access proxy. The proxy evaluates a batch of access requests against a central policy and filters out any requests that fail to meet authorization, location, or posture requirements.

Function contract

Implement solve(requests: list, policy: dict) -> list in the code editor (see the Reference section below).

Input

  • requests: A list of dictionaries representing connection requests. python requests = [ { "id": "REQ-001", "user": "alice", "role": "doctor", "resource": "ehr_db", "ip": "192.168.1.50", "device_posture": {"antivirus_ok": True, "disk_encrypted": True} } ]
  • policy: A dictionary detailing the security rules. python policy = { "allowed_roles": { "ehr_db": ["doctor", "admin"], "mri_machine": ["admin", "technician"] }, "requires_internal": ["ehr_db", "mri_machine"], "requires_posture": ["ehr_db"], "internal_prefixes": ["192.168.1.", "10.0."] }

Output

A list of strings representing the ids of requests that are allowed, maintaining their original order.

Entry point

def solve(requests: list, policy: dict) -> list

Input (requests, policy)

  • requests: list[dict], List of connection requests. Each request is a dictionary with:
  • id: str, Unique request identifier.
  • user: str, Username.
  • role: str, User role (e.g., "doctor", "guest", "admin").
  • resource: str, Destination resource name.
  • ip: str, Source IP address.
  • device_posture: dict[str, bool], Key-value pairs of health posture checks.
  • policy: dict, Zero-trust access policy specification containing:
  • allowed_roles: dict[str, list[str]], Resource name mapped to list of allowed roles.
  • requires_internal: list[str], List of resources requiring an internal IP address.
  • requires_posture: list[str], List of resources requiring full device posture compliance.
  • internal_prefixes: list[str], List of IP address prefix strings considered internal.

Output (result)

list[str], List of ids of the requests that are allowed, preserving their original order.

Policy Rules

For a connection request to be allowed, it must satisfy all of the following: 1. Role Authorization: The request's role must be in the allowed_roles list for the requested resource. If the resource is not in allowed_roles, it is automatically denied. 2. Network Isolation: If the resource is in the requires_internal list, the request's ip must start with one of the prefixes in the internal_prefixes list. 3. Posture Check: If the resource is in the requires_posture list, all checks within the request's device_posture dictionary must be True. If device_posture has no checks, it is considered compliant.

Guarantees / rules

  • Pure function, deterministic, no I/O, no network.
  • Standard library only.
  • Output list preserves the relative order of allowed request IDs from the input.
