3.3.a, VLANs and network segmentation

Before class today. Networks that treat every connected device as equally trusted are far more dangerous than they appear. When an attacker compromises one machine on a flat network, a network where every device can freely reach every other device, they inherit access to printers, file servers, cameras, payroll databases, and anything else plugged into the same broadcast domain.

The intuition to hold onto: The image worth holding onto walking in: a flat network is a building with no interior walls, where a fire that starts in the lobby reaches the server room with nothing in its way. VLANs are those interior walls, built in switch software rather than drywall, and the entire justification for segmentation is that a compromise of one device should never automatically mean a compromise of everything plugged into the same switch. That's the direct payoff of 3.1.a's flat-network warning from the start of this unit, this skill is where you finally get the tool that actually builds the walls it warned you were missing.

A myth worth busting before we start: "A VLAN is the same as a separate physical network." A VLAN is a logical separation on shared hardware. Physical separation (an air gap) provides stronger isolation, but VLANs are practical and sufficient for most environments when firewall rules are enforced at the routing boundary.

Today's goal: Explain what a VLAN is, describe how network segmentation limits the spread of an attack, and assign hosts to VLANs to enforce separation between different trust zones. Handout: pre-lecture-handout.docx.
