3.1.b, DNS attacks (spoofing, cache poisoning)

Before class today. The Domain Name System (DNS) is the directory service of the internet, translating human-friendly names (like example.com) into computer-routable IP addresses (like 192.0.2.1). Because almost every internet connection starts with a DNS lookup, compromising this process allows an attacker to redirect traffic silently and globally.

The intuition to hold onto: The intuition to carry in: DNS is a race, and the attacker doesn't need to be strong, just fast and lucky enough times in a row. Because DNS runs over UDP with no session and no built-in verification, a forged reply that arrives before the real one wins outright, not because it's more convincing, but because the resolver has no way to tell a real answer from a fake one except "which one showed up first." That's a genuinely uncomfortable fact to sit with: an entire layer of internet infrastructure that billions of devices depend on every day is, at its core, a guessing game about a 16-bit number.
