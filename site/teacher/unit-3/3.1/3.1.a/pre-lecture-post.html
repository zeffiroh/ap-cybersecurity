TCP/IP fundamentals and network topology flaws

Unit 3 · Securing Networks · 3.1 Network-Level Exploits

Before class today. Every network attack starts with a target: a device, a service, or a data stream that an attacker wants to reach, disrupt, or spy on. To understand how attacks work, and how defenses fail, you first need to understand the underlying plumbing. That plumbing is TCP/IP, a family of protocols that governs how data moves between any two points on the internet or a private network.

The intuition to hold onto: Hold onto this framing before the lecture even starts: TCP/IP was built for a network of people who already trusted each other, and every structural weakness this skill covers is just that original assumption of trust refusing to die. Nobody added authentication to IP addresses or ARP because nobody in 1975 imagined a stranger would want to lie about who they were. That's not a bug that slipped through code review, it's the entire internet's foundation being built for a world that no longer exists. Once you see the stack that way, IP spoofing and ARP spoofing stop looking like clever hacks and start looking like the completely predictable consequence of never having asked "but what if the sender lies?"

A myth worth busting before we start: "Switches make sniffing impossible." → Switches reduce passive sniffing but MAC flooding and ARP spoofing let attackers redirect traffic through their own machine even on switched networks.

Today's goal: Describe how the TCP/IP protocol stack works, identify structural weaknesses in common network topologies, and explain how those weaknesses create attack surfaces that adversaries exploit. Handout: pre-lecture-handout.docx.
