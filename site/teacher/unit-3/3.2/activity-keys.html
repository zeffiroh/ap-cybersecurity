Topic 3.2 Activity Answer Keys

Wireless Network Security · instructor-only · 3 entries

Skill 3.2.a

Wi-Fi basics and wireless security protocols (WPA2/WPA3)

Instructor notes

  • Expected classifications: A=secure, B=acceptable (password length below 20 is the gap), C=insecure (TKIP + short password + outdated firmware), D=insecure (WEP is completely broken), E=secure, F=insecure (password too short).
  • Common stumble: students accept WPA2-TKIP as "just WPA2." Clarify that TKIP reintroduced RC4 weaknesses and must be rejected; AES-CCMP is the only acceptable WPA2 cipher.
  • This activity feeds the unit 3 project (network security assessment) and scenario stage 3 (the attacker uses an evil-twin AP because the target network still uses WPA2-PSK with a weak password).
Skill 3.2.b

Managerial controls and security policies

Answer key (instructor only)

# Type Reasoning
1 Managerial A signed policy document governing behavior.
2 Technical MFA is enforced automatically by software/hardware at login.
3 Physical Restricts physical entry to a space, regardless of the reader being electronic.
4 Managerial A documented, recurring access-review process (least privilege policy in action).
5 Gap No managerial control exists; a documented lost-device / incident policy is needed.

Instructor notes

  • Timing: rows 1-2 are the core rule cases; row 3 is the deliberate "electronic but still physical" teaching moment; row 4 tests recognition of an ongoing process as managerial rather than technical; row 5 requires students to author policy language themselves.
  • Common stumble: students assume anything involving a device or electronics must be "technical" — reinforce that the classification depends on WHAT the control restricts (access to a physical space vs. automatic software/hardware enforcement vs. documented behavior/process), not on whether it involves technology.
  • Feeds forward to the Unit 3 project, where students build a full control matrix for a fictional small business network.
Skill 3.2.c

Layered network defense overview

Answer key (instructor only)

# Layer Reasoning
1 Perimeter Filters traffic at the network boundary before it reaches internal systems.
2 Network Segments traffic between internal zones.
3 Host Protects the individual device's operating system.
4 Application Protects the application's own logic/inputs.
5 Data Protects the data itself regardless of application or device.
6 Human A policy document governing behavior, spanning all technical layers.

Instructor notes

  • Timing: rows 1-2 are straightforward layer placements; row 3 is the deliberate "why not perimeter" teaching moment; rows 4-5 test the application-vs-data distinction, which students often conflate.
  • Common stumble: students place every technical-sounding control at the "network" layer by default, reinforce that each layer has a specific scope (boundary, internal segmentation, individual device, application code, data itself).
  • This activity is designed as a capstone review for the whole 3.1-3.2 sequence: every control from 3.1.b-3.2.b should be placeable somewhere in this model, and instructors should draw that connection explicitly during report-out.
