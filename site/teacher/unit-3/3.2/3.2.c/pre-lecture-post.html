3.2.c, Layered network defense overview

Before class today. Every control studied so far in Unit 3, DNS protections (3.1.b), ARP/MITM defenses (3.1.c), encryption against packet sniffing (3.1.d), strong Wi-Fi protocols (3.2.a), and managerial policy (3.2.b), addresses a specific threat at a specific point. None of them, alone, protects an organization completely.

The intuition to hold onto: Walk into this skill already knowing its punchline, because it's worth having ahead of time: every control this unit has covered so far, DNSSEC, ARP inspection, encryption, WPA3, an AUP, only stops one specific kind of attack, and none of them overlaps with any of the others. WPA3 does nothing whatsoever against DNS poisoning. DNSSEC does nothing whatsoever against a socially engineered password handover. That's not a weakness in any individual control; it's the reason defense in depth exists as a principle at all, and this skill is where all of Unit 3's separate pieces finally get organized into one picture instead of feeling like a list of unrelated topics.

A myth worth busting before we start: "The strongest single control is better than several weaker ones." → Different controls defend against different, non-overlapping attack vectors; an attacker only needs to find the one gap a single-control strategy leaves open. Depth matters more than any individual control's strength.

Today's goal: Explain the principle of defense in depth, place a given security control at the correct layer of a layered network defense model, and evaluate why relying on any single control creates a single point of failure. Handout: pre-lecture-handout.docx.
