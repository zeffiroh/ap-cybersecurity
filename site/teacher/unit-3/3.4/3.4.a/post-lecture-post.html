Firewall types (stateful vs. stateless)

Unit 3 · Securing Networks · 3.4 Firewall Access Controls

  • Simulation: SimLab
  • Self-check quiz: due before next class

The big picture: The scenario worth remembering by name is the spoofed RST packet: a stateless firewall sees TCP, port 80, allowed and waves it through, because a stateless firewall genuinely cannot ask whether this is part of a connection that actually exists, it has no memory to ask that question with. A stateful firewall's connection-tracking table is what makes that question askable at all, and that's precisely why stateful inspection defeats a whole category of spoofing and session-hijacking attacks that a stateless ruleset simply cannot see. Don't let stateful expand in your head into smart, though, this skill is explicit that stateful inspection tracks connection state, not payload content; malware riding inside an already-permitted HTTPS session sails straight through a stateful firewall because the firewall's only question is whether the session is established, not what's actually inside it. That gap, connection-aware but content-blind, is exactly the opening the next atom's ACL precision starts to narrow, and it's also the reason 3.5's IDS/IPS atom needs to exist at all: something has to inspect what a stateful firewall, by design, does not.

Key terms to lock in:

  • Stateless (packet-filter) firewall: examines each packet independently against a fixed rule set; no memory of prior packets or connection state.
  • Stateful (stateful-inspection) firewall: maintains a connection-tracking table; permits return traffic for established sessions and drops packets that do not match any tracked session.
  • Connection-tracking table: data structure the firewall uses to record active sessions (source IP, destination IP, ports, protocol, and connection state).
  • Packet header: the metadata portion of a packet (IP addresses, ports, flags, protocol) that both firewall types examine.
  • TCP three-way handshake: the SYN / SYN-ACK / ACK exchange that establishes a TCP session; stateful firewalls use this to know when a connection is legitimately open.

Common misconceptions to watch for:

  • "A stateful firewall is always more secure than a stateless one." → Stateful is more aware of connection context, but security also depends on the rules written. A stateful firewall with a rule that permits all inbound traffic is still insecure.
  • "Stateful firewalls inspect the content of packets." → Stateful inspection tracks connection state, not application payload. Content inspection is a separate, application-layer function.
  • "Stateless firewalls are obsolete." → They are still used where performance and simplicity matter, such as high-throughput edge routers or embedded devices with limited CPU.
