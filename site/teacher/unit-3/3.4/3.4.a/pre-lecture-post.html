Firewall types (stateful vs. stateless)

Unit 3 · Securing Networks · 3.4 Firewall Access Controls

Before class today. Every network sits behind some form of gatekeeper, a device that decides which packets may enter or leave. The firewall is the most fundamental of those gatekeepers. Before you can configure one, you need to understand how it thinks about traffic.

The intuition to hold onto: The question to carry into this lecture: does the firewall remember anything, or does it wake up with total amnesia before every single packet? That's the entire stateless-versus-stateful distinction in one sentence, and it's worth having ready because the exam scenario that trips students up almost always hinges on exactly this, a packet that looks perfectly legitimate in isolation (correct port, correct protocol, an ACK bit set) but that no real connection ever actually started.

A myth worth busting before we start: "A stateful firewall is always more secure than a stateless one." → Stateful is more aware of connection context, but security also depends on the rules written. A stateful firewall with a rule that permits all inbound traffic is still insecure.

Today's goal: Distinguish stateless from stateful firewalls, explain how each inspects traffic, and identify which type is better suited to a given threat scenario. Handout: pre-lecture-handout.docx.
