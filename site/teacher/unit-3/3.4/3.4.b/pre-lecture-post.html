3.4.b, Firewall rules and access control lists (ACLs)

Before class today. A firewall's decisions are only as good as the rule list it is given. That rule list is called an access control list (ACL): an ordered sequence of statements, each specifying an action (allow or deny) and a set of matching conditions, source address, destination address, destination port, and protocol.

The intuition to hold onto: The one fact worth having memorized before you even open this lecture: order is not a formatting choice in an ACL, it is the entire logic of the ACL. First-match-wins means a firewall stops reading the instant a packet matches any rule, so the identical set of rules written in a different order can produce a completely different, and completely wrong, security outcome, with zero code changed, only the order of lines on a page.

A myth worth busting before we start: "The order of ACL rules doesn't matter as long as all the right rules exist." → Order is everything under first-match-wins; a correct rule placed after a broader matching rule never fires.

Today's goal: Write and evaluate an ordered firewall access control list (ACL), correctly apply first-match-wins evaluation, and identify when a rule's placement creates a security gap by shadowing a more specific rule below it. Handout: pre-lecture-handout.docx.
