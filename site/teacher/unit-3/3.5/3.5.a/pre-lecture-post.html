3.5.a

Intrusion detection and prevention systems (IDS/IPS)

Unit 3 · Securing Networks · 3.5 Network Threat Detection

Before class today. A firewall decides what traffic is allowed in and out. An intrusion detection or prevention system watches traffic that has already been permitted and asks a harder question: does this allowed traffic actually look like an attack? The difference matters because many attacks travel over ports and protocols that firewalls must leave open, HTTP on port 80, DNS on port 53, encrypted traffic on port 443.

The intuition to hold onto: The question worth carrying into lecture: what happens to traffic a firewall already decided to let through? That's the gap this skill lives in, a firewall answers whether a port is allowed, but plenty of real attacks travel over ports that have to stay open (HTTP, DNS, HTTPS), which means allowed and safe are two different questions, and IDS/IPS exists specifically to keep asking the second one after the firewall has already answered the first.

A myth worth busting before we start: "IDS and IPS are the same thing." → IDS only alerts; IPS actively blocks. A misconfigured IPS with a high false-positive rate will drop legitimate traffic and cause outages.

Today's goal: Distinguish between intrusion detection systems (IDS) and intrusion prevention systems (IPS), explain how signature-based and anomaly-based detection work, and identify which alert type (true positive, false positive, true negative, false negative) a given scenario represents.
