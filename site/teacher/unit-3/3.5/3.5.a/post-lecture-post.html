The big picture: Keep signature-based and anomaly-based detection sorted by what each one trades away: signatures are precise and fast but structurally blind to anything new, since a zero-day by definition has no entry in the database yet; anomaly detection can catch a never-before-seen attack precisely because it doesn't need a signature at all, but it pays for that with a much higher false-positive rate, since unusual and malicious are not the same thing. The TP/FP/FN/TN grid is worth being fluent in cold, because the exam's favorite trap is treating false positives as merely annoying, they're actually dangerous precisely because enough of them causes analysts to start tuning out real alerts, and an ignored true positive is functionally identical to a system that never detected anything at all. Common misconceptions -- don't fall for these: - "IDS and IPS are the same thing." → IDS only alerts; IPS actively blocks. A misconfigured IPS with a high false-positive rate will drop legitimate traffic and cause outages. - "Signature-based IDS catches all attacks." → Only attacks with existing signatures are caught. Zero-days and novel variants pass through undetected unless anomaly or behavioral detection is also in place. - "More alerts = better security." → Alert fatigue from excessive false positives degrades security by causing analysts to stop investigating alerts. Tuning and prioritization matter as much as detection capability.
