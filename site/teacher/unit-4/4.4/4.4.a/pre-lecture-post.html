Endpoint detection and response (EDR)

Unit 4 · Securing Devices · 4.4 Endpoint Threat Auditing

Before class today. Every device on a network, laptop, server, or workstation, is a potential entry point for an attacker. A firewall guards the boundary, but once malicious code is running inside a machine, a boundary control cannot see it. Endpoint Detection and Response (EDR) is the category of security software that watches activity on the device itself rather than at the network edge.

The intuition to hold onto: The reframe to make before this lecture starts: a firewall is a guard standing at the front door, and EDR is a guard who already lives inside the building, the moment malicious code is actually running on a device, a boundary control can no longer see it, because the code isn't crossing the boundary anymore, it's already past it. Everything interesting about EDR follows from that one positional difference: it has to watch behavior happening on the machine, in real time, which is a fundamentally different job than inspecting traffic as it crosses a perimeter.

A myth worth busting before we start: "EDR is just better antivirus." -> Antivirus primarily checks files against known signatures at rest. EDR monitors continuous runtime behavior across process, file, network, and registry streams and can respond by isolating, killing, or quarantining, not just scanning.

Today's goal: Describe how an EDR platform collects telemetry from a device, explain how it classifies process and file activity as suspicious or clean, and identify the core actions an EDR takes when it detects a threat. Handout: pre-lecture-handout.docx.
