Identifying compromised devices (indicators of compromise)

Unit 4 · Securing Devices · 4.4 Endpoint Threat Auditing

Before class today. EDR (4.4.a) watches live behavior on a device, and log analysis (4.4.b) correlates events over time. Both techniques ultimately produce the same kind of output: individual clues that something is wrong. An indicator of compromise (IOC) is a piece of forensic evidence, an artifact left behind on a system or network, that suggests a device has been breached.

The intuition to hold onto: Carry this question into the lecture: if you found just one of these clues on a device, a new admin account, say, would you be confident it was an attack? Almost certainly not; an IT technician doing routine maintenance produces the exact same artifact. That ambiguity is the whole reason this skill exists: an indicator of compromise is evidence, not proof, and the skill being taught is exactly the same one from log analysis one atom ago, refusing to trust a single data point and instead asking what the combination of data points implies.

A myth worth busting before we start: "Any single suspicious artifact proves a device is compromised." → One IOC alone is usually ambiguous and may have an innocent explanation. Confident verdicts come from combining multiple independent IOCs, similar to correlating multiple log entries in 4.4.b.

Today's goal: Define an indicator of compromise (IOC), classify common IOC categories, and combine multiple IOCs on a single device into an overall compromise verdict using weighted scoring. Handout: pre-lecture-handout.docx.
