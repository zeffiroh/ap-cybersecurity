1. Brief

The situation. Each device under investigation reports a set of observed indicators of compromise (IOCs). Each IOC type carries a fixed severity weight. Build the scoring engine that sums the weights of the IOCs observed on a device and returns an overall compromise verdict.

Lesson objective. Define an indicator of compromise (IOC), classify common IOC categories, and combine multiple IOCs on a single device into an overall compromise verdict using weighted scoring.

What comes in

A list of strings, each an IOC type observed on one device. Duplicate entries in the list count only once (an IOC type either is or is not present on the device).

What must come out

One of the strings: "clean" (total score < 4), "suspicious" (4 <= total score < 8), "compromised" (total score >= 8).

Entry point

def solve(iocs: list) -> str

Input (iocs)

A list of str IOC type identifiers observed on a single device. Duplicates may appear in the list but each IOC type is counted at most once toward the total score.

IOC weight table

WEIGHTS = {
    "known_malicious_hash": 6,
    "av_disabled": 5,
    "new_admin_account": 4,
    "unusual_outbound_traffic": 3,
    "unexpected_scheduled_task": 3,
    "registry_run_key_added": 2,
    "failed_login_cluster": 1,
}

Any string not present in this table contributes a weight of 0.

Output (result)

One of "clean", "suspicious", "compromised", based on the total score (sum of unique matched weights): - score < 4 -> "clean" - 4 <= score < 8 -> "suspicious" - score >= 8 -> "compromised"

Guarantees / rules

  • Pure function, deterministic, no I/O, no network.
  • Standard library only unless the hidden grading tests: allow_deps` lists otherwise.
  • Duplicate IOC type strings in the input are de-duplicated before scoring.
  • Unrecognized IOC strings do not raise; they simply add 0 to the score.
  • Thresholds are as specified above (lower bound inclusive, upper bound exclusive per band).
