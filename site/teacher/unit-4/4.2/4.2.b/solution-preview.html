Multi-factor authentication (MODEL SOLUTION, instructor copy, do not distribute)

Coding problem, 4.2.b: Classify a login attempt's MFA strength

Skill: Mitigate Risk · Maps to: 4.2.A, 4.2.B · Language: Python 3 (pytest)

Problem

A security analyst receives, for each login attempt, the list of authentication factors that were presented (e.g. ["password", "sms_code"]). Build the classifier that determines whether the attempt satisfies true multi-factor authentication, and if so, whether it relies on a phishing-resistant possession factor or a phishable one.

Categories of result: - "single_factor", the presented factors, once mapped to their factor category (knowledge / possession / inherence), cover fewer than two distinct categories. This includes presenting only one factor, presenting several factors from the same category (e.g. two passwords), an empty list, or a list of only unrecognized factor strings. - "mfa_phishing_resistant", two or more distinct factor categories are present, and at least one of the presented factors is a phishing-resistant possession factor (hardware_key or fido2). - "mfa_phishable", two or more distinct factor categories are present, but no phishing-resistant possession factor was used (e.g. it relies on sms_code, totp_code, authenticator_app, push_approved, or backup_code for the possession factor).

The exact factor-to-category mapping and full rule set are defined in the Reference section below, implementations must follow it precisely.

Function contract

Implement solve(factors: list[str]) -> str in the code editor (see the Reference section below).

Input

A list of strings, each a recognized or unrecognized factor name. May be empty.

Output

One of: "single_factor", "mfa_phishable", "mfa_phishing_resistant".

Examples

["password"]                          -> "single_factor"
["password", "password"]              -> "single_factor"
["password", "security_question"]     -> "single_factor"
["password", "sms_code"]              -> "mfa_phishable"
["password", "push_approved"]         -> "mfa_phishable"
["password", "hardware_key"]          -> "mfa_phishing_resistant"
["password", "sms_code", "hardware_key"] -> "mfa_phishing_resistant"
["biometric", "password"]             -> "mfa_phishable"
[]                                     -> "single_factor"

Constraints

  • Deterministic, offline, standard library only.
  • Follow the exact factor -> category mapping in the Reference section below.
  • Unrecognized factor strings must not raise an error; they are simply ignored.
  • Must pass all cases in the tests (visible + hidden).

Entry point

def solve(factors: list[str]) -> str

Input (factors)

A list of strings, each naming an authentication factor presented during one login attempt, e.g. ["password", "hardware_key"]. Order does not matter. The list may be empty.

Factor -> category mapping (exact, case-sensitive strings)

factor string category phishing-resistant?
password knowledge n/a
pin knowledge n/a
security_question knowledge n/a
sms_code possession no
totp_code possession no
authenticator_app possession no
push_approved possession no (unverified push approval; MFA-fatigue risk)
backup_code possession no
hardware_key possession yes
fido2 possession yes
biometric inherence no

Any string not in this table is an unrecognized factor and is ignored when determining categories (it does not count toward the category set and does not trigger phishing-resistant status), but it does not cause an error.

Output (result)

Exactly one string from {"single_factor", "mfa_phishable", "mfa_phishing_resistant"}.

Classification rules

  1. Map every string in factors to a category using the table above; unrecognized strings map to no category and are skipped.
  2. Let distinct_categories be the set of distinct categories (knowledge, possession, inherence) actually present among recognized factors.
  3. If len(distinct_categories) < 2 (this includes an empty list, an all-unrecognized list, and a list where every recognized factor maps to the same single category, e.g. two knowledge credentials): return "single_factor".
  4. Otherwise (2 or more distinct categories are present):
  5. If any recognized factor is a phishing-resistant possession factor (hardware_key or fido2): return "mfa_phishing_resistant".
  6. Otherwise: return "mfa_phishable".

Phishing-resistance takes priority: if a phishing-resistant possession factor is present alongside any number of phishable factors, the result is still "mfa_phishing_resistant".

Guarantees / rules

  • Pure function, deterministic, no I/O, no network. Standard library only.
  • Does not raise on empty lists or unrecognized factor strings.
  • Returns a single string (not a list).
