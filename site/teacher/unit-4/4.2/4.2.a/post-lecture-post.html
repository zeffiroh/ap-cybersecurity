The big picture: The throughline worth naming explicitly is that every rule in a password policy is a direct, traceable answer to a named attack: minimum length answers brute-force, banning breached passwords answers dictionary attacks and credential stuffing, salted slow hashing (bcrypt/Argon2, never MD5 or SHA-1) answers what happens after a database is stolen, and lockout thresholds answer online guessing specifically, with duration itself becoming a tradeoff between stopping an attacker and accidentally letting an attacker lock out a legitimate user as a denial-of-service move. That's the pattern to keep applying for the rest of Unit 4.2: authentication controls always come in this shape, a defense mapped tightly to one specific attack, which is exactly why 4.2.b exists at all, passwords, however well policed, are still just one factor, and a single leaked secret (however strong) grants full access forever until someone notices and changes it.

Key terms to lock in: - Authentication, verifying the identity of a user or system before granting access. - Brute-force attack, systematically trying every possible password until one succeeds. - Dictionary attack, trying passwords from a list of common words, names, and patterns. - Salt, a unique random value added to a password before hashing to defeat precomputed attacks. - Account lockout, temporarily blocking an account after a threshold of failed login attempts. - Password policy, a set of rules an organization enforces on the creation and management of passwords. - NIST SP 800-63B, the US federal password guideline that underpins most modern enterprise policy.

Common misconceptions -- don't fall for these: - "Complexity rules (uppercase + symbol) make passwords strong." -> Complexity rules push users toward predictable patterns (P@ssw0rd1). Length and unpredictability matter more. NIST removed mandatory complexity in 2017. - "Changing your password every 90 days improves security." -> Forced rotation produces predictable families ("Spring2024!", "Summer2024!"). Rotate only when there is evidence of compromise. - "Blocking copy-paste in the password field is a security feature." -> It forces shorter, weaker passwords and prevents password manager use. It is an anti-pattern.
