Coding problem, 4.2.d: Access-request auditor

Skill: Mitigate Risk · Maps to: 4.2.B, 4.2.C · Language: Python 3 (pytest)

Problem

A security team reviews access requests before granting them. Each request either has a business justification attached or it does not; the requester's access may or may not have been reviewed recently; and the requested access may be scoped to a temporary time window or be standing (permanent). Build the auditor function that applies the least-privilege triage rules to a single request and returns the decision.

Function contract

Implement def solve(request: dict) -> str in the code editor (see the Reference section below).

Input

A dict with keys current_role (str), requested_access (str), justification_present (bool), time_bound (bool or None), last_reviewed_days_ago (int). Optional keys default as documented in the Reference section below (missing justification_present defaults to False; missing time_bound defaults to False; missing last_reviewed_days_ago defaults to 0).

Output

One of the strings: "approve", "deny_no_justification", "flag_privilege_creep", "approve_time_bound".

Decision rule (apply in this exact order, first match wins)

  1. No justification (justification_present is False) → "deny_no_justification".
  2. Else, stale review (last_reviewed_days_ago > 365) → "flag_privilege_creep".
  3. Else, time-bound request (time_bound is True) → "approve_time_bound".
  4. Else → "approve".

Rule 1 is checked before rule 2, a request with no justification is denied even if it is also years overdue for review or time-bound. The staleness threshold is 365 days, strictly greater than (365 itself is still considered current).

Entry point

def solve(request: dict) -> str

Input (request)

A dict describing one access request:

key type required default if missing meaning
current_role str no "" the requester's current job role (informational; not used in the decision below, but always present in well-formed data)
requested_access str no "" the resource/access level being requested (informational)
justification_present bool yes False whether a business justification was submitted with the request
time_bound bool or None no False whether the requested access is scoped to a fixed, temporary time window; None is treated the same as False
last_reviewed_days_ago int no 0 days since this requester's access was last reviewed/recertified

Missing optional keys default as shown above. justification_present is required conceptually (it drives the first rule) but if the key is absent, treat it as False (fail closed).

Output (result)

Exactly one string from {"approve", "deny_no_justification", "flag_privilege_creep", "approve_time_bound"}.

Decision rule (exact priority order, evaluate top to bottom, return on first match)

  1. If justification_present is False (or missing) → return "deny_no_justification". This is checked FIRST and overrides every other condition, including privilege creep.
  2. Else if last_reviewed_days_ago > 365 → return "flag_privilege_creep". A stale access review (more than 365 days since last review) takes priority over approving, even if the request is time-bound. The threshold is a strict greater-than: exactly 365 does NOT trigger this rule.
  3. Else if time_bound is True → return "approve_time_bound".
  4. Else → return "approve".

Guarantees / rules

  • Pure function, deterministic, no I/O, no network.
  • Standard library only unless the hidden grading tests: allow_deps` lists otherwise.
  • Missing optional keys use the defaults in the table above; do not raise on missing keys.
  • last_reviewed_days_ago == 365 is NOT stale (rule 2 requires strictly greater than 365).
