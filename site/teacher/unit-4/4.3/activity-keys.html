Topic 4.3 Activity Answer Keys

Endpoint Hardening Controls · instructor-only · 3 entries

Skill 4.3.a

Device hardening

Instructor notes

  • Expected findings: default credentials (Administrator/admin, Guest enabled), unneeded services (FTP, Telnet, HTTP server all unnecessary for a workstation), firewall disabled, disk encryption off, no screen lock.
  • Common stumble: students treat all missing controls as equally important. Guide them to rank by likely exploitation path, default credentials and disabled firewall are typically highest risk.
  • Feeds the unit project (device security audit) and scenario stage 3 (attacker pivots from hardened network to poorly configured workstation).
Skill 4.3.b

Antivirus and endpoint protection

Instructor notes

  • Expected Rule A: IF process path is NOT in C:\Program Files\* AND process modifies >10 files in <5 seconds THEN block.
  • Expected Rule B: IF process listens on a port AND spawns a shell (cmd.exe or powershell.exe) without user interaction/authorization prompt THEN block.
  • Expected Rule C: IF powershell.exe is spawned by an Office application (winword.exe, excel.exe) AND makes an outbound network connection THEN block. Emphasize that the scheduled/interactive nature of Process F (2 AM maintenance window, launched from an admin's own session) is what distinguishes it, not the tool itself.
  • Guide students to recognize that path restrictions (like C:\Windows\* or C:\Program Files\*) and process parentage are critical clues in separating admin tasks from user-space malware.
  • Scenario C reinforces the atom's "living-off-the-land" concept: the malicious tool is a legitimate system binary, so behavior and context (parent process, timing, destination), not identity, must drive the detection rule.
Skill 4.3.c

Patching and regular updates

Instructor notes

  • Expected priority order (highest urgency first): B (public-facing, actively exploited, patch immediately/emergency), D (public-facing, working exploit published, patch urgently), A (critical severity but internal and not yet exploited, patch on an accelerated but not emergency timeline), E (high severity but no patch will ever exist, apply compensating controls, e.g. network isolation/segmentation, not patching), C (low severity, low exposure, routine cadence).
  • Common stumble: students rank purely by CVSS number and miss that exposure (internet-facing) and exploitation status (already being exploited) matter as much as or more than raw severity. A high CVSS score on an isolated internal system can be less urgent than a moderate score on an actively-exploited public system.
  • Card E is the deliberate trick card: it forces students to realize "patch" is not always the answer, end-of-life systems require compensating controls instead.
  • Feeds the coding problem's exact triage logic (severity + exploitation + exposure -> urgency label) and reinforces the unit's defense-in-depth theme.
