The big picture: The four-part checklist, change defaults, remove what's unneeded, enable protective features, lock down accounts, is really least privilege from 4.2.d applied to a machine instead of a person, and it's worth seeing them as the same discipline wearing two hats: a device that only runs the services its job requires has a smaller blast radius for exactly the same reason an account with only the access it needs does. The idea that should stick longest, though, is configuration drift: hardening is not a one-time checklist you complete and move on from, it's a state that constantly decays as administrators install software, open a port "temporarily," or reset something during troubleshooting, which is precisely why mature programs pair hardening with automated tools (Ansible, Puppet, Group Policy) that continuously re-check the live device against a known-good baseline. Keep that idea active through the rest of 4.3: hardening removes unnecessary risk before an incident, endpoint protection (4.3.b) catches malicious activity that a hardened device still lets through, and patching (4.3.c) closes the vulnerabilities that hardening alone can't touch because they're bugs in code the device actually needs to run.

Key terms to lock in:

  • Device hardening: the process of systematically removing or disabling unnecessary features, services, and accounts to reduce a device's attack surface before deployment.
  • Attack surface: the total set of points where an unauthorized user could attempt to interact with or exploit a system.
  • Default credentials: factory-set usernames and passwords that are identical across many units of the same device model and are publicly known.
  • Principle of least privilege: every account and process should operate with only the minimum permissions required for its legitimate function.
  • Configuration baseline: a documented record of the approved secure state of a device, used as a reference to detect and correct drift.
  • Configuration drift: the gradual accumulation of unauthorized or unintended changes to a device's configuration over time.

Common misconceptions to watch for:

  • "Only servers need hardening." → Every device with a network connection, laptops, printers, phones, cameras, has an attack surface and must be hardened.
  • "Changing the password is enough." → Changing the default password is the single most important first step, but a hardened device also disables unneeded services, enables protective features, and restricts account privileges.
  • "Hardening is a one-time task." → Configuration drift means hardening must be monitored continuously; a hardened device today may have re-opened attack surfaces tomorrow.
