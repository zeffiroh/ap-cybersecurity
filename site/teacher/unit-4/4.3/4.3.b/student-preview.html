1. Brief

The situation. Endpoint Protection Platforms (EPP) use a mixture of signature detection (known hashes) and behavioral heuristics (actions taken by the process, such as excessive file updates or network socket connections) to identify and suspend threats.

You are tasked with writing a process-auditing rule engine solve(data). The engine evaluates a list of running processes against: 1. A database of known malicious file hashes (signatures). 2. Max thresholds on process behavior: max_file_modifications and max_network_connections.

The function must return a list of PIDs of all processes that violate any of these rules.

Lesson objective. Explain the difference between signature-based and heuristic/behavioral malware detection, describe the function of host-based firewalls, and explain how endpoint protection platforms (EPP) safeguard devices in an enterprise.

Entry point

def solve(data: dict) -> list[int]

Input (data)

A dictionary containing: - "signatures": list of strings (MD5 hashes of known malware) - "behavioral_rules": dict with keys: - "max_file_modifications" (int) - "max_network_connections" (int) - "processes": list of dicts, where each dict has: - "pid" (int) - "name" (string) - "hash" (string) - "file_modifications" (int) - "network_connections" (int)

Output (result)

A list of integers representing the PIDs of flagged processes. A process is flagged if: 1. Its hash is in the "signatures" list. 2. Its "file_modifications" is strictly greater than "max_file_modifications". 3. Its "network_connections" is strictly greater than "max_network_connections".

The output list of PIDs must be sorted in ascending order. If no processes are flagged, returns [].

Guarantees / rules

  • Pure function, deterministic, no I/O, no network.
  • Standard library only.
  • Case-insensitivity: MD5 hash comparisons should be case-insensitive (e.g., "A1B2" matches "a1b2").

Acceptance

Your code passes when every test below shows a checkmark (some are hidden until you run them).
