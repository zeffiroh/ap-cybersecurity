Coding problem, 4.3.c: Patch-prioritization engine

Skill: Mitigate Risk · Maps to: 4.3.B, 4.3.C · Language: Python 3 (pytest)

Problem

A patch-management team needs to triage a queue of pending vulnerabilities and decide how urgently each must be addressed. Each vulnerability has a CVSS severity score, a flag for whether it is being actively exploited in the wild, a flag for whether the affected asset is internet-facing, and a flag for whether the affected software is end-of-life (no patch will ever be released). Build the triage engine that assigns one urgency label to each vulnerability.

Function contract

Implement def solve(vulns: list) -> list in the code editor (see the Reference section below).

Input

A list of dicts, each with keys: id (str), cvss (float, 0.0-10.0), exploited_in_wild (bool), internet_facing (bool), end_of_life (bool).

Output

A list of dicts, one per input vulnerability (same order as input), each with keys id (str, copied from input) and urgency (str), where urgency is one of: "emergency", "scheduled", "routine", "compensate".

Decision rule (apply in this exact order, first match wins, per vulnerability)

  1. end_of_life is True → "compensate" (no patch will ever exist; patching is not an option regardless of severity or exploitation status).
  2. Else, exploited_in_wild is True AND internet_facing is True → "emergency".
  3. Else, cvss >= 9.0 AND internet_facing is True → "emergency" (a working exploit is likely imminent for a critical, internet-facing flaw even without confirmed in-the-wild activity).
  4. Else, cvss >= 9.0 → "scheduled" (critical severity but not internet-facing).
  5. Else, cvss >= 7.0 AND internet_facing is True → "scheduled".
  6. Else → "routine".

Rule order matters: end_of_life is checked first and overrides every other condition, an end-of-life system is never "emergency" or "scheduled" even at CVSS 10.0, because patching is not a valid remediation at all.

Examples

[{"id": "V1", "cvss": 9.1, "exploited_in_wild": True, "internet_facing": True, "end_of_life": False}]
    -> [{"id": "V1", "urgency": "emergency"}]

[{"id": "V2", "cvss": 8.8, "exploited_in_wild": False, "internet_facing": False, "end_of_life": True}]
    -> [{"id": "V2", "urgency": "compensate"}]

[{"id": "V3", "cvss": 4.2, "exploited_in_wild": False, "internet_facing": False, "end_of_life": False}]
    -> [{"id": "V3", "urgency": "routine"}]

Constraints

  • Deterministic, offline, standard library only.
  • Preserve input order in the output list.
  • Exactly one urgency label per vulnerability.
  • Must pass all cases in the tests (visible + hidden).

Entry point

def solve(vulns: list) -> list

Input (vulns)

A list of dicts, each describing one vulnerability:

key type meaning
id str vulnerability identifier, echoed unchanged into the output
cvss float CVSS severity score, 0.0-10.0
exploited_in_wild bool whether the vulnerability is confirmed being actively exploited
internet_facing bool whether the affected asset is reachable from the public internet
end_of_life bool whether the affected software is end-of-life (no patch will ever ship)

Output (result)

A list of dicts, same length and same order as the input, each with: - "id": the same id string from the corresponding input entry - "urgency": one of "emergency", "scheduled", "routine", "compensate"

Decision rule (exact priority order, evaluate top to bottom per vulnerability, return on

first match) 1. If end_of_life is True → "compensate". This overrides everything else, no CVSS score or exploitation status changes this, because patching an end-of-life product is not possible. 2. Else if exploited_in_wild is True and internet_facing is True → "emergency". 3. Else if cvss >= 9.0 and internet_facing is True → "emergency". 4. Else if cvss >= 9.0 → "scheduled". 5. Else if cvss >= 7.0 and internet_facing is True → "scheduled". 6. Else → "routine".

Guarantees / rules

  • Pure function, deterministic, no I/O, no network.
  • Standard library only unless the hidden grading tests: allow_deps` lists otherwise.
  • CVSS thresholds are inclusive (>=), not strict.

# Reference solution """Reference solution for 4.3.c. MUST pass 100% of the tests. Also the default 'blackbox' implementation students can swap out (see the hidden grading tests).""" def solve(vulns: list) -> list: """Assign an urgency label to each vulnerability per the patch-triage priority rules. Args: vulns: list of dicts with keys id (str), cvss (float), exploited_in_wild (bool), internet_facing (bool), end_of_life (bool). Returns: list of dicts, same order, each {"id": ..., "urgency": ...} where urgency is one of "emergency", "scheduled", "routine", "compensate". """ results = [] for v in vulns: vid = v["id"] cvss = v.get("cvss", 0.0) exploited = v.get("exploited_in_wild", False) internet_facing = v.get("internet_facing", False) end_of_life = v.get("end_of_life", False) if end_of_life: urgency = "compensate" elif exploited and internet_facing: urgency = "emergency" elif cvss >= 9.0 and internet_facing: urgency = "emergency" elif cvss >= 9.0: urgency = "scheduled" elif cvss >= 7.0 and internet_facing: urgency = "scheduled" else: urgency = "routine" results.append({"id": vid, "urgency": urgency}) return results
