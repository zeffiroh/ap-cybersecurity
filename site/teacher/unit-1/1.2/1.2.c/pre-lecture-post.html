1.2.c, Strengthening authentication: length/complexity, randomness, MFA

Before class today. The previous atom showed what makes a password weak. This skill asks the harder question: what makes authentication genuinely strong? The answer has three layers, length, randomness, and a second factor, and understanding all three changes how you design and evaluate authentication systems.

The intuition to hold onto: It's worth pausing on why TOTP specifically, not SMS, not email, became the default second factor: the whole scheme works offline, with zero network trust required at verification time. Both the phone and the server independently compute the same 30-second-windowed function of a shared secret and the clock. No code ever crosses a network where it could be intercepted, spoofed, or SIM-swapped. That's a fundamentally different security posture than SMS codes, which do travel over an inherently interceptable carrier network, and it's why this skill asks you to build TOTP from hmac/hashlib yourself: once you've computed a code by hand, "the app just knows" stops being magic and becomes math you own.

A myth worth busting before we start: "MFA is unbreakable." → TOTP codes can be phished in real-time (the attacker relays the code immediately). MFA raises the bar dramatically but does not eliminate social engineering.
