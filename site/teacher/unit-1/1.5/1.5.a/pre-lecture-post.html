AI reviewing security configurations

Unit 1 · Introduction to Security · 1.5 AI-Powered Threat Detection

Before class today. Every server, network device, and cloud service is controlled by a configuration file, a plain-text document that specifies exactly how the system behaves. Get that file right and you have a hardened system. Get it wrong and you have an open door.

The intuition to hold onto: The professor's frame for the whole AI-in-defense half of this unit: every tool from here on out follows the same pattern, AI does the exhaustive, mechanical, tireless part (does this directive match a known-bad pattern, across every line, with zero fatigue) and a human does the contextual judgment part (is this exception documented, is this a legitimate compensating control). Keep asking, for every AI-assisted tool you meet from here forward, "what exactly is the machine automating, and what judgment is still reserved for the human?", that question is the fastest way to actually understand what a tool does rather than just what it's called.

A myth worth busting before we start: "Default settings are safe because the vendor tested them." → Defaults are tuned for compatibility and ease of setup, not for security. Hardening requires deliberate reconfiguration.

Today's goal: Describe how AI-assisted tools audit security configuration files for common misconfigurations, identify specific insecure settings in a sample config, and explain why automated review catches issues that manual checklists often miss. Handout: pre-lecture-handout.docx.
