1. Brief

The situation. Build the pattern-matching core of an AI code security scanner. Given a string of Python source code, return a sorted list of vulnerability tags for every dangerous pattern found. This is the rule-evaluation layer that tools like Bandit and Semgrep implement under the hood.

Lesson objective. Explain how AI-powered static analysis scans source code for known vulnerability patterns, identify specific risky constructs in Python code, and articulate why each flagged pattern creates a security risk.

What comes in

A single string, the entire source code to scan. May be multi-line or empty.

What must come out

A sorted list[str] of vulnerability tags drawn from: - "vuln:eval" - "vuln:hardcoded_password" - "vuln:md5" - "vuln:os_system" - "vuln:pickle_loads" - "vuln:subprocess_shell"

<details><summary>Reference: the exact contract</summary>

Any implementation that satisfies this interface can be swapped in (reference, student, or composite) and must pass the tests unchanged.

Entry point

def solve(code: str) -> list[str]

Input (code)

A single string containing Python source code to scan. May be multi-line. May be empty.

Output (result)

A sorted, de-duplicated list[str] of vulnerability finding tags. Return [] if no patterns are found.

Pattern rule set (case-sensitive substring search unless noted)

Tag returned Trigger substring Vulnerability class
"vuln:eval" eval( Code injection via eval
"vuln:os_system" os.system( OS command injection
"vuln:subprocess_shell" shell=True OS command injection via subprocess
"vuln:md5" md5( Broken cryptographic hash (MD5)
"vuln:pickle_loads" pickle.loads( Unsafe deserialization
"vuln:hardcoded_password" password = Hardcoded credential in source

Notes: - password = matching is case-insensitive (matches Password =, PASSWORD =, etc.). - All other patterns are case-sensitive (Python identifiers are case-sensitive). - A single line may trigger multiple tags if multiple patterns are present. - Comments are NOT excluded, a dangerous call inside a comment still triggers the tag. (In practice, AST-based tools skip comments; here we use substring scan for transparency.)

Guarantees / rules

  • Pure function, deterministic, no I/O, no network. Standard library only.
  • Output always sorted ascending (lexicographic) and de-duplicated.
  • solve("") returns [].

Acceptance

Your code passes when every test below shows a checkmark (some are hidden until you run them).

3. Build it

from typing import List RULES = [ ("vuln:eval", "eval(", True), ("vuln:hardcoded_password", "password =", False), ("vuln:md5", "md5(", True), ("vuln:os_system", "os.system(", True), ("vuln:pickle_loads", "pickle.loads(", True), ("vuln:subprocess_shell", "shell=True", True), ] def solve(code: str) -> List[str]: if not code: return [] findings = set() for tag, trigger, case_sensitive in RULES: haystack = code if case_sensitive else code.lower() needle = trigger if case_sensitive else trigger.lower() if needle in haystack: findings.add(tag) return sorted(findings)
