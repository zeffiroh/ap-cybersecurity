AI suggesting detection rules

Unit 1 · Introduction to Security · 1.5 AI-Powered Threat Detection

Before class today. A security operations center (SOC) can receive millions of log events per day from firewalls, servers, identity providers, and endpoint agents. No human team can read every line. The first line of defense is a set of detection rules: machine-readable conditions that trigger an alert when log events match a pattern known to be suspicious.

The intuition to hold onto: Detection rules are where the abstract idea of "pattern recognition" from earlier atoms becomes a concrete, deployable artifact: a condition, a threshold, and an action, expressed in a format a machine can act on without a human re-reading every log line. The brute-force rule, five failures per minute, is worth remembering not for the specific number but for what the number represents: someone, at some point, tuned that threshold against real data to balance catching real attacks against drowning analysts in false alarms. Every threshold you'll ever configure in security tooling is fighting that same precision-recall tradeoff.

A myth worth busting before we start: "More rules = better security." → More rules means more alerts. If rules are not precise, analysts are buried in noise and real threats get lost. Quality and tuning matter more than quantity.

Today's goal: Explain how AI-assisted tools generate detection rules from log data, implement a rule-generation algorithm that converts repeated suspicious events into structured rule strings, and evaluate what makes a generated rule operationally useful versus noisy. Handout: pre-lecture-handout.docx.
