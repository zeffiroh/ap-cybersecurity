Public Network Sniffing · instructor-only · 4 entries

Skill 1.3.a

Adversary skill levels (low-skilled vs high-skilled / zero-days); motivation

Instructor notes

  • Expected answers: Alex = low, Blake = high, Casey = high (rule 2), Dana = high (rule 1), Emery = low (targeted but not adaptive).
  • Common stumble: students classify Emery as high because they "target a victim." Emphasize that rule 2 requires BOTH targeting AND adaptation.
  • Feeds the unit project (public-Wi-Fi threat model) and scenario stage 1 (attacker profiling before the evil-twin and jamming stages).
Skill 1.3.b

Evil twin attack

Instructor notes

  • Expected suspicious rows: 2 (CafeGuest OPEN vs. WPA2), 4 (Airport-Free duplicate BSSID, both OPEN, but two BSSIDs for a single-AP public network is suspicious). Row 5 (CorpNet single BSSID, WPA3) is intentionally clean; some students flag it anyway, redirect them to the rule: a single BSSID alone is not an indicator.
  • Common stumble: students flag strong signal as the sole indicator. Clarify: stronger signal is a tiebreaker, not a primary indicator, BSSID anomaly and security mismatch are primary.
  • Feeds the unit project (wireless risk report) and scenario stage 2 (evil-twin interception).
Skill 1.3.c

Jamming / denial-of-service attack

Instructor notes

  • Expected answers: A = clean (only one spike at position 3); B = jamming (positions 2-7 are all above 80, run = 6); C = clean (all below 80); D = jamming (positions 2-10 are above 80, run = 9); E = jamming (positions 1-10 are above 80, run = 10).
  • Common stumble: students count the threshold as inclusive vs. exclusive. The rule uses strictly greater than T (> 80), so a sample of exactly 80 does not count. Verify with series C (max 76 = clean) vs. series B (min 82 = jamming).
  • Feeds the unit project (wireless threat report) and scenario stage 3 (detecting the physical intrusion support operation).
Skill 1.3.d

War driving; protecting yourself (verify SSIDs, avoid open networks, VPN)

Instructor notes

  • Expected flags by card: Card 1: open-network, unverified-ssid, no-vpn. Card 2: none (clean). Card 3: unverified-ssid. Card 4: open-network, no-vpn (ssid IS verified, that flag clears). Card 5: unverified-ssid, no-vpn.
  • Common stumble: students think WPA2 without verification is safe. Clarify: security type addresses encryption, but an evil twin can use WPA2 too, verification is a separate check.
  • Card 2 is intentionally clean to check that students do not over-flag.
  • Feeds the unit project (personal security policy) and scenario stage 4 (user connects to evil twin due to missing verification step).
