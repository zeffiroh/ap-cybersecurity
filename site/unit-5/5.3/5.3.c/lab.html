Lab, Integrity, Authenticity, and HMAC

Forge a message past a plain hash, then watch a secret key stop the same forgery.

Every hash and tag below is computed by your browser's real cryptography (SHA-256 and HMAC via Web Crypto). You will play the attacker on a channel that protects a bank transfer with a plain hash, rewrite the message, and recompute the hash so the tampering passes. Then you switch the channel to HMAC, which mixes in a secret key you do not have, and discover the same forgery is rejected. That is the line between integrity and authenticity.

Integrity is not authenticity

A plain hash answers only "does this data match this digest?" Because SHA-256 is public and keyless, an attacker who alters the message can simply recompute the digest, and the receiver's check passes. That gives integrity against accidental corruption, not against a deliberate forger. HMAC folds a secret key into the computation, so a valid tag proves the sender knew the key, which an attacker does not. Tampering changes the message, the recomputed tag no longer matches, and the forgery is caught. This is the integrity-versus-authenticity distinction at the heart of LO 5.3.B and 5.3.C.
