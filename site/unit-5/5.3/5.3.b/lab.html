Lab, Why a Nonce Must Never Repeat

Reuse one counter in a stream cipher and watch a second message fall out of the first.

All encryption below is real AES-CTR run by your browser's Web Crypto, under one secret key that never changes. AES-CTR is a stream cipher: it turns the key and a nonce (the starting counter) into a keystream, then XORs that keystream with your plaintext. The security rests on one rule, never reuse a nonce with the same key. You will see why: encrypt two messages under the same counter and the keystream cancels out, so C1 XOR C2 = P1 XOR P2. If you know the first message, you recover the second with no key at all.

The nonce is the whole defense

AES-CTR encrypts by generating a keystream from (key, nonce) and XORing it with the plaintext: C = P XOR KS. If two messages reuse the same key and nonce, they share the same keystream, so C1 XOR C2 = (P1 XOR KS) XOR (P2 XOR KS) = P1 XOR P2, the keystream vanishes. Any known or guessable plaintext then peels the other message open, with no key required. This is exactly the flaw that broke WEP (topic 3.2). A unique nonce per message, plus disciplined key lifecycle management, is the control named in LO 5.3.A and 5.3.B; authenticated modes such as AES-GCM add integrity on top. The algorithm was never broken here, the operating practice was.
