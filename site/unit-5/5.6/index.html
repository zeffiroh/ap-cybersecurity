5.6Application Threat Auditing

  • LO 5.6.A: Account for how an attack against stored data becomes visible at all, which record of the event exists, which system wrote it, and what an analyst must compare it against before it means anything.
  • LO 5.6.B: Choose the controls that will actually produce that evidence for a given application and a given threat, rather than assembling a collection of tools that all watch the same thing.
  • LO 5.6.C: Judge a detection method on what it can and cannot see, the noise it generates per true finding, how quickly it fires, what it costs to operate, and whether an adversary can disable it.
  • LO 5.6.D: Determine whether a file is the file it should be by computing its digest and comparing that against a trusted reference, and recognise when the reference is not trustworthy.
  • LO 5.6.E: Read a sequence of log records well enough to name the attack, assess whether it succeeded, and write the result as a report someone else can act on without repeating the analysis.
