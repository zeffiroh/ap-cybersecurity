Lab, File Integrity Monitoring

Record a known-good baseline, then let a hash catch files the attacker quietly changed.

Logs record what an application did; a file integrity monitor records what its files are. Every hash below is computed by your browser's real SHA-256 (Web Crypto). You will capture a baseline digest of each server file, let an attacker tamper with some of them without telling you which, and use the baseline to pinpoint exactly what changed. Then you will verify a downloaded file against the publisher's posted hash, the same check you should run on any software you install.

What integrity monitoring buys, and its limit

A cryptographic hash is a fingerprint: change a single byte and the digest changes completely, so comparing a file's current hash to a stored baseline reveals tampering that a casual look would miss, a web shell appended to a page, a backdoor added to a cron job, a flipped config flag. The same check verifies that downloaded software matches what the publisher released. The catch is twofold: FIM detects change only after it happens, so it is a detective control, not a preventive one; and the baseline itself must be stored where the attacker cannot also rewrite it, off-host or in append-only, tamper-evident storage, or the attacker simply updates the baseline to match their altered file. This is the detection discipline behind LO 5.6.A.
