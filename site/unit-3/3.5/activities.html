3.5 Activities

Network Threat Detection · 3

Skill 3.5.a · pairs · 25 min · Offline: yes

Intrusion detection and prevention systems (IDS/IPS)

Goal

Students can distinguish IDS from IPS, classify IDS alert outcomes (TP/FP/FN/TN), and explain the trade-off between sensitivity and false-positive rate. Ties to LO 3.5.A (identify IDS/IPS roles and detection methods).

Materials

Steps

Check off all materials above to unlock the steps.
  1. Each pair opens the simulation and works through the 6 alert scenarios. For each scenario they must agree on the classification (TP/FP/FN/TN) and write one sentence justifying their choice before submitting.
  2. After completing the sim, pairs discuss: which two outcomes (TP/FP/FN/TN) represent failures? Which is more dangerous and why?
  3. Pairs are given the following tuning scenario: "The IDS flags 200 alerts per day; analysts can investigate 50. The security manager asks whether to raise or lower the sensitivity threshold." Each pair writes a recommendation (one paragraph) and explains the trade-off.

Collaborate

Assign roles: one partner is the "IDS analyst" (classifies each alert and defends the call), the other is the "SOC manager" (challenges the classification, is there evidence it is really benign/malicious?). Swap roles halfway through.

Exit Ticket

AP

Certificate of Completion

Each student submits: (1) a one-sentence definition distinguishing IDS from IPS, and (2) an example of why a false negative is more dangerous than a false positive in a healthcare network.

Skill 3.5.b · pairs · 25 min · Offline: yes

Network monitoring and traffic analysis

Goal

Students compare a printed traffic baseline against an observed traffic window for a small set of Meridian High School hosts and identify which hosts show a genuine anomaly (unusual port, volume spike, or beaconing pattern) versus which are within normal variation. Ties to LO 3.5.B (read flow data, apply a baseline, identify monitoring indicators of compromise).

Materials

Printed baseline and observed traffic (deterministic)

Baseline (normal daily profile):
Host          Max bytes/day   Allowed ports
10.0.1.5      500,000,000     445, 139        (file server)
10.0.2.9      5,000,000       80, 443         (staff workstation)
10.0.2.14     5,000,000       80, 443         (staff workstation)
10.0.3.20     2,000,000       80, 443, 3389   (lab workstation, RDP allowed)
10.0.4.2      50,000,000      25, 587         (mail relay)

Observed traffic window (one school day):
Host          Total bytes sent   Ports used        Notes
10.0.1.5      420,000,000        445               Normal file-share load
10.0.2.9      4,800,000          80, 443           Normal browsing
10.0.2.14     1,200,000          443, 4444         Small volume but port 4444 never seen before
10.0.3.20     2,900,000          80, 443, 3389     Volume slightly over baseline
10.0.4.2      50,900 (x60, one connection every ~60 sec to same external IP)   587   Regular-interval beacon pattern

Expected classifications: 10.0.1.5 = normal, 10.0.2.9 = normal, 10.0.2.14 = ANOMALY (unusual port 4444), 10.0.3.20 = ANOMALY (volume 2.9M > 2M baseline), 10.0.4.2 = ANOMALY (beaconing pattern, regular ~60-second interval connections, even though total volume and port are within baseline).

Steps

Check off all materials above to unlock the steps.

  1. Read the baseline (5 min). Each pair reviews the baseline table: normal daily byte volume and allowed ports for five hosts.

  2. Score the observed window (12 min). Pairs review the observed-traffic table (one school day) and, for each host, decide: within baseline, or anomalous? If anomalous, they name the specific indicator (unusual port, volume spike, or beaconing).

  3. Justify (8 min). For each host they flag, pairs write one sentence citing the specific number or port that crossed the baseline.

Collaborate

Assign roles: one partner is the "monitoring analyst" (applies the baseline mechanically), the other is the "SOC lead" (challenges each call, is the deviation big enough to matter, or could it be legitimate?). Swap roles for two instructor-supplied hosts.

Exit Ticket

AP

Certificate of Completion

Each student writes: one host from the table, its anomaly type (or "normal"), and one sentence explaining what makes 10.0.4.2's case different from a simple volume or port anomaly (regular timing, not just what/how much).

Skill 3.5.c · small group (3-4) · 25 min · Offline: yes

Incident response sequence

Goal

Groups reconstruct the correct NIST SP 800-61 phase order for a shuffled set of response actions taken during a Meridian High School ransomware incident, and articulate why two "obviously sensible" out-of-order actions would actually make the incident worse. Ties to LO 3.5.C (order incident-response actions correctly; explain the risk of skipping or reordering phases).

Materials

Printed action cards (deterministic, shuffled)

Card 1: "Rebuild the file server from a verified clean backup and reconnect it to the network."
Card 2: "Delete the attacker's backdoor scheduled task from the domain controller."
Card 3: "Draft and rehearse the school's incident response plan with IT staff."
Card 4: "Confirm that the ransomware alert is a real compromise, not a false positive."
Card 5: "Disconnect the infected lab subnet from the rest of the network."
Card 6: "Write an incident timeline and update the response plan based on what was learned."
Card 7: "Immediately wipe and reinstall the infected machine while it is still on the live network." [TRAP]
Card 8: "Patch the vulnerability the attacker used to gain initial access."
Card 9: "Monitor the recovered systems closely for any sign the compromise persists." [TRAP if placed too early]

Correct order (by phase): - Preparation: Card 3 - Identification: Card 4 - Containment: Card 5 - Eradication: Card 2, Card 8 (Card 7 belongs here too, but ONLY after containment, see trap notes) - Recovery: Card 1, Card 9 - Lessons Learned: Card 6

Steps

Check off all materials above to unlock the steps.

  1. Sort the cards (10 min). Each group receives the 9 shuffled action cards below. Working together, they sort them into the correct 6-phase NIST order (some phases have more than one action; keep same-phase actions grouped but their internal order does not need to be graded).

  2. Spot the trap (8 min). Two of the cards are deliberately written to tempt an out-of-order placement (see "trap" notes below, not shown to students). Groups discuss why each trap action must wait for an earlier phase to finish first.

  3. Present (7 min). Each group presents their final order and defends the placement of the two trap actions to the class.

Collaborate

Assign roles: a "recorder" (writes the final order), a "skeptic" (challenges any placement without a clear phase justification), and a "presenter" (defends the group's order to the class).

Exit Ticket

AP

Certificate of Completion

Each student writes: which two cards are the "traps," and one sentence each explaining what goes wrong if Card 7's action happens before the subnet is disconnected (Card 5), and if Card 9's monitoring is treated as optional after recovery.
