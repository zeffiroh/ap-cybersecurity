Lab, Firewall Rules and First-Match-Wins

Write an ordered ACL, replay traffic through it, and watch rule order decide who gets in.

A firewall evaluates its rules top to bottom and stops at the first match. Anything that matches no rule hits the default deny. You will write an access control list, replay a fixed set of packets through it, and see exactly which rule decided each one. Then you will build the classic ordering mistake, a broad allow that shadows a specific deny below it, and fix it. Rule format, one per line:

action proto src dst dport  —  e.g. allow tcp any 10.0.0.5 443. Use any as a wildcard. Lines starting with # are comments.

Why order is a security control

A firewall ACL is not a set, it is a sequence. Because evaluation stops at the first match, a broad allow placed above a specific deny shadows it: the deny can never run, and the traffic it was meant to block sails through. The fix is not a new rule but a new order, specific rules first, broad rules last, and an explicit default deny at the bottom. This is the first-match-wins evaluation and rule-shadowing gap named in LO 3.4.B and 3.4.C. In production the same discipline applies to cloud security groups and host firewalls, where one over-broad allow at the top quietly undoes everything below it.
