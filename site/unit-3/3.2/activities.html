3.2 Activities

Wireless Network Security · 3

Skill 3.2.a · pairs · 25 min · Offline: yes

Wi-Fi basics and wireless security protocols (WPA2/WPA3)

Goal

Students evaluate six printed Wi-Fi configuration cards and classify each as secure, acceptable, or insecure. By the end, each pair produces a written justification for every classification and articulates one concrete remediation step for each insecure card. Ties to LO 3.2.A (evaluate controls that protect a network).

Materials

Wi-Fi Configuration Card Set (print and cut)

Card A: protocol=WPA3, password_length=22, guest_vlan=yes, firmware=current Card B: protocol=WPA2-AES, password_length=18, guest_vlan=no, firmware=current Card C: protocol=WPA2-TKIP, password_length=8, guest_vlan=no, firmware=outdated Card D: protocol=WEP, password_length=10, guest_vlan=no, firmware=outdated Card E: protocol=WPA3, password_length=25, guest_vlan=yes, firmware=current Card F: protocol=WPA2-AES, password_length=6, guest_vlan=yes, firmware=current

Steps

Check off all materials above to unlock the steps.
  1. Each pair reads atom.md (or opens the simulation) to confirm the criteria for secure vs. insecure. Criteria: protocol must be WPA2-AES or WPA3; password length at least 20 characters; guest VLAN isolated; firmware current.
  2. Working together, classify each card (secure / acceptable / insecure) using the criteria. Record the classification and a one-sentence reason on the answer sheet.
  3. For each insecure card, write one concrete remediation step, the exact change an admin would make (e.g., "upgrade protocol to WPA3 and regenerate a 24-character random password").
  4. Open the simulation and run the configuration classifier simulation. Compare the simulation's verdict for each card to your written answer. Note any discrepancy and discuss why.

Collaborate

Assign roles within each pair: one is the "network admin" who argues for the current configuration, the other is the "security auditor" who flags gaps. After classifying all six cards, swap roles and revisit any card where you disagreed. Write a final joint verdict.

Exit Ticket

AP

Certificate of Completion

Each student submits (individually, written or typed): - Which card was the most ambiguous to classify, and why? - State the one criterion you found most impactful for security and justify it in two sentences.

Skill 3.2.b · small group (3-4) · 25 min · Offline: yes

Managerial controls and security policies

Goal

Groups act as a security program team building a control matrix for a small company, classifying each existing control by family (managerial, technical, physical) and identifying one gap where a managerial control is missing. Ties to LO 3.2.A, 3.2.B and the course skill Mitigate Risk.

Materials

Scenario list (print or project)

# Scenario Control type?
1 New hires sign an AUP before receiving a laptop. ?
2 The office VPN requires MFA for remote login. ?
3 The finance office door requires a keycard. ?
4 Managers review each employee's file-share access every 6 months. ?
5 The company has no documented policy for what happens when a laptop is lost or stolen. (gap, discuss)

Steps

Check off all materials above to unlock the steps.
  1. (5 min) Each group reads rows 1-2 individually and classifies them (managerial, technical, physical) using the three-family rule from the lesson.
  2. (5 min) Group discusses row 3: is a keycard door reader a "technical" control (it's electronic) or a "physical" control (it restricts physical access)? Resolve using the lesson's definition, what the control restricts, not what it's made of.
  3. (7 min) Group works row 4: this is a recurring process, not a single event. Decide whether it's managerial or technical, and explain how it relates to "privilege creep."
  4. (5 min) Each group opens the simulation and checks their calls against the sim's scoring for analogous scenarios; groups revise any incorrect calls.
  5. (3 min) Row 5 (the gap): each group drafts one sentence of what a lost-device policy should require (e.g., mandatory reporting window, remote wipe authorization, password reset).

Collaborate

Assign roles: one member is the "policy author" (drafts language for row 5's missing policy), one is the "auditor" (challenges whether each classification in rows 1-4 is correct), and remaining members are "control matrix builders" (compile the group's final table mapping scenario -> type). For row 3, the group must specifically debate the keycard reader's classification and defend their answer using the lesson's definition rather than intuition about "electronics = technical."

Exit Ticket

AP

Certificate of Completion

Each student writes one sentence: "Scenario X is a [MANAGERIAL / TECHNICAL / PHYSICAL] control because [it governs behavior via policy / it enforces automatically via hardware-software / it restricts physical access]."

Skill 3.2.c · small group (3-4) · 25 min · Offline: yes

Layered network defense overview

Goal

Groups act as security architects building a defense-in-depth diagram for a small business network, placing every control studied in Unit 3 into its correct layer and identifying which layer has the fewest controls (a potential weak point). Ties to LO 3.2.B, 3.2.C and the course skill Mitigate Risk.

Materials

Control list (print or project)

# Control Layer?
1 DNS filtering blocking known-malicious domains at the gateway. ?
2 Internal firewall between the guest VLAN and the corporate VLAN. ?
3 OS patch management keeping every laptop's operating system current. ?
4 Web Application Firewall (WAF) in front of the customer portal. ?
5 Data Loss Prevention (DLP) tooling blocking sensitive files from leaving via email. ?
6 The company's Acceptable Use Policy, signed by every employee. ?

Steps

Check off all materials above to unlock the steps.
  1. (5 min) Each group reads rows 1-2 individually and assigns a layer using the six-layer model from the lesson (perimeter, network, host, application, data, human).
  2. (5 min) Group discusses row 3: why is OS patching a host-layer control rather than a perimeter-layer control, even though vulnerable software could be exploited remotely?
  3. (7 min) Group works rows 4-5 together: both protect something inside the network, but at different layers (application vs. data). Discuss the distinction: WAF protects the application logic itself; DLP protects the data regardless of which application touches it.
  4. (5 min) Each group opens the simulation and checks their calls against the sim's scoring for analogous scenarios; groups revise any incorrect calls.
  5. (3 min) Report-out: each group tallies how many controls landed in each layer for their table and identifies which layer has the fewest, is that a real gap, or just outside today's list?

Collaborate

Assign roles: one member is the "architect" (assigns each control to a layer and defends the reasoning), one is the "auditor" (challenges each assignment against the lesson's definitions), and remaining members are "gap analysts" (identify which layer is thinnest and propose one additional control for it). For row 6 (AUP), the group must specifically explain why a policy document, not a piece of hardware or software, still counts as a defense layer.

Exit Ticket

AP

Certificate of Completion

Each student writes one sentence: "Control X belongs in the [PERIMETER / NETWORK / HOST / APPLICATION / DATA / HUMAN] layer because [reasoning tied to what it protects and how]."
